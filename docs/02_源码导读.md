#### ★ 必须理解的 ESP-NOW 信道机制（`espnow_link.h` 文件头有完整说明）

```
本模块不初始化 WiFi，也不设置信道。
ESP-NOW 走 STA 接口 → 自动跟随 STA 所在信道 → STA 连上路由器后即为该路由器的信道。
                     ↓
仪表主表把信道【硬编码为 1】(其 espnow_link.c 的 ESPNOW_CHANNEL)
                     ↓
★ 硬约束：路由器/热点必须工作在【信道 1】，否则收不到任何包
```

#### 诊断函数（判断「为什么收不到数据」）

| 函数 | 判读 |
|---|---|
| `espnow_slave_rx_count()` | 累计有效包数 |
| `espnow_slave_rx_mismatch_count()` | **>0 且长时间无有效包** → 射频活着但收到别人的流量 → **大概率信道不对**<br>**恒为 0** → 这个信道上没有 ESP-NOW 流量 → 主表没开或太远 |
| `espnow_slave_last_rx_age_ms()` | 距今多久没收到（从未收到返回 -1） |
| `espnow_slave_master_name()` | 最近听到的主表名字 |
| `espnow_slave_self_test()` | 无第二块板时验证「收包→解析→缓存」逻辑（`ESPNOW_SLAVE_SELF_TEST=1` 自动跑一次） |

## 四、双向接口契约

### 4.1 ESP-NOW 广播包（主表 → 从表）

**必须与主表 `espnow_obd_packet_t` 完全一致**（`espnow_link.c` 第 66 行起）：

```c
typedef struct __attribute__((packed)) {
    uint16_t magic;              // 0x4F42 ('OB')
    uint8_t  version;            // 5（v5 起含 afr_x100）
    uint8_t  flags;              // bit0: 主表已连 ELM327；bit1: 联动测试中
    uint32_t seq;                // 递增序号，用于丢包诊断
    uint16_t rpm;
    uint8_t  speed;
    uint8_t  sweep_step;         // 扫表进度（200+ = 展示模式槽位）
    uint8_t  intro_step;         // 开机动画进度
    int16_t  coolant_temp;
    int16_t  intake_temp;
    int16_t  oil_temp;
    int16_t  oil_pressure_x10;   // 0.1 bar
    int16_t  boost_x10;          // 0.1 bar
    int16_t  brake_temp_x10;     // 0.1 °C
    int16_t  load_pct;
    int16_t  tps;
    int32_t  bat_mv;             // 毫伏
    int16_t  afr_x100;           // 空燃比 ×100
    char     name[12];           // 主表名，MASTER_NAME_LEN = 12
} espnow_obd_packet_t;
```

| 常量 | 值 | 位置 |
|---|---|---|
| `ESPNOW_MAGIC` | `0x4F42` | `espnow_link.c:44` |
| `ESPNOW_VER` | `5` | `espnow_link.c:45` |
| `MASTER_NAME_LEN` | `12` | `espnow_link.c:46` |
| 广播信道 | **1（硬编码在主表侧）** | 从表侧 `ESPNOW_BROADCAST_CHANNEL = 0`（跟随 STA） |
| 主表名 | `"SkyGauge"` | 主表 `espnow_link.c` |

**无效值哨兵（两边必须一致）**：

| 字段 | 无效值 |
|---|---|
| `oil_temp` | `-100` |
| `oil_pressure_x10` | `-1` |
| `boost_x10` | `-32768` |
| `brake_temp_x10` | `-1000` |
| `afr_x100` | `-1` |
| `load_pct` / `tps` | `-1` |
| `bat_mv` | `-1` |

## 六、改代码前的三条铁律

1. **改 LVGL 控件/样式前必须 `DisplayLockGuard`**
   —— 包括「只改字体」这种看似无害的操作。

2. **字体 / 图片 / 主题是「运行时会重建的资源」**
   —— **不要把指针缓存到控件上**，重建后就是野指针。

3. **新增被 include 的头文件后，第一次改它不会触发重编**
   —— Ninja 依赖尚未建立 → **删对应 `.obj` 强制重编**。

> 更多坑（40 个缺陷台账 + 试过走不通的路）见
> [`../开发参考/18-迭代日志-结构变更与缺陷台账.md`](../开发参考/18-迭代日志-结构变更与缺陷台账.md)。
