## 一、这是什么

把 [小智 AI](https://github.com/78/xiaozhi-esp32)（xiaozhi-esp32）改造成一块**圆形车载仪表**：
插 OBD 口读车况，ESP-NOW 无线送到方向盘旁的圆屏上，同时保留语音对话能力。

| 项 | 值 |
|---|---|
| 从表（= 本仪表面板） | 微雪 **ESP32-S3-Touch-LCD-1.85**，SKU 28514，360×360 圆屏，ST77916（QSPI），CST816S 触摸，16 MB flash / 8 MB PSRAM |
| 主表（= 车上的数据源） | **同一型号板**，跑上游 `obd_brz_gauge` 固件 |
| OBD 适配器 | Vgate iCar Pro 2S（BLE ELM327） |
| 车辆 | 马自达阿特兹 2020 运动版，协议 **6**（ISO 15765-4 CAN@500k） |
| 项目状态 | **台架全链路已验证；上车首测未完成** |

### 数据链路

```
                  BLE                    ESP-NOW 2.4GHz              QSPI
 车 ── OBD2 ──► Vgate iCar Pro 2S ──► 主表 ESP32 ──► (信道 1) ──► 从表 ESP32 ──► 360×360 圆屏
                                          │                            │
                                    读 PID ~10Hz                 显示 + 语音（小智云端）
                                    广播 100ms/包
```

**关键数量关系**：主表经 BLE 读 PID 只有 **约 10 Hz**。这是本项目一切动画问题的源头 ——
表盘必须**插值**才顺，否则转速弧就是每秒跳 10 次。详见 [`../开发参考/24`](../开发参考/24-主表固件帧率优化与IDF5.5.3环境.md)。

## 三、环境事实（不照做必失败）

> 这一节的每一条都是踩坑换来的。**不要凭经验绕过。**

### 铁律 ①：工程路径必须纯英文无空格

| 内容 | 中文 | 空格 |
|---|---|---|
| ESP-IDF 工程目录 | ❌ 禁止 | ❌ 禁止 |
| ESP-IDF 安装目录 | ❌ 禁止 | ❌ 禁止 |
| 文档 / ZIP | ✅ 可以 | ✅ 可以 |

ESP-IDF 工具链对非 ASCII 路径脆弱。历史上 `D:\Atz 仪表台`（中文+空格）**直接让会话工作目录失效**。
详见 [`../开发参考/11`](../开发参考/11-路径规范与工作区说明.md)。

> ⚠️ **本机存在一个反面教材**：`D:\AIWorkbuddy\仪表\AtzGauge` 是含中文的副本，
> 且**缺少主表可构建工程**。**不要在那里编译，也不要拿它当交接基线。**

### 铁律 ②：两个 ESP-IDF，版本不同，不可互换

| 工程 | 需要的 IDF | 安装位置 | 为什么 |
|---|---|---|---|
| `xiaozhi-esp32/src`（从表） | **v6.1** | `D:\esp` | 上游小智要求 |
| `obd_brz_gauge/repo`（主表） | **v5.5.3** | `D:\esp553` | 上游仪表工程锁定（LVGL 8.4） |

两套工具链**各自独立安装**（主表那套用 `tools/install-idf553.ps1` 装，共享 `D:\esp\tools` 工具目录）。
**IDF 永远不能靠复制迁移** —— 里面是 6 GB+ 二进制且路径烙死，目标机必须重跑安装脚本。

### 铁律 ③：两个工程都必须走 Python 启动器，不能用 `.ps1` 包装脚本

```bash
# ✅ 从表（IDF v6.1 @ D:\esp）
python tools/idf61-run.py --cmd "python scripts/build.py waveshare/esp32-s3-touch-lcd-1.85-atzgauge"

# ✅ 主表（IDF v5.5.3 @ D:\esp553）
python tools/idf553-run.py build
python tools/idf553-run.py -p COM3 app-flash

# ❌ 直接调 idf.py：会静默 exit 0，什么都不做
# ❌ 用 tools/idf-run.ps1：会「成功」跑完但环境没激活，cmake 找不到 ninja/git
```

**有两条独立的原因，都会让构建失败，而且失败方式都很误导：**

**原因 A —— 环境被重新注入。**
本机 shell 会向**每个子进程**注入 `MSYSTEM=MINGW64` 与固定 PATH。于是：

- `idf.py` 开头有 `if 'MSYSTEM' in os.environ:` —— 命中后**只打一句警告、根本不调用 `main()`**，
  表现为「命令成功但什么都没编译」；
- cmake（`idf.py` 的子进程）看不到 ninja/git/xtensa-esp-elf，报
  `unable to find a build program corresponding to "Ninja"` / `Could NOT find Git`。

`unset MSYSTEM` 与改 PATH **都无效**（改动传不到子进程）。
唯一可靠解法是 Python `subprocess(env=...)` 显式构造环境。

**原因 B —— PowerShell 执行策略是 `Restricted`。**
`tools/idf-run.ps1` 内部要 dot-source `tools/activate-idf.ps1` 来激活 IDF 环境，
但执行策略禁止运行脚本 → dot-source 被拒。而该脚本的 `$ErrorActionPreference = 'Continue'`
**不会因此停止**，于是它打印完横幅、拿着**完全未激活的环境**去跑命令
→ cmake 找不到 ninja/git。**看起来像工程坏了，其实只是环境没设。**

**因此两个启动器都改用 Python 直连**（`tools/idf61-run.py` / `tools/idf553-run.py`），
各自手工构造 PATH 并用 `subprocess(env=...)` 拉起 `idf.py`。

> ⚠️ **两个启动器不可混用，工具版本选择方向相反**：
> 它们共享 `D:\esp\tools` 这一个 `IDF_TOOLS_PATH`，里面同时装着两套工具：
>
> | 工具 | v5.5.3（主表） | v6.1（从表） |
> |---|---|---|
> | cmake | **3.30.2** | **4.0.3** |
> | xtensa-esp-elf | **esp-14.2.0** | **esp-15.2.0** |
>
> `idf553-run.py` 取**较旧**的一套，`idf61-run.py` 取**较新**的一套。选错直接构建失败。
>
> ⚠️ 另外 `idf61-run.py` 会把命令开头的 `python` **自动换成 IDF 虚拟环境的解释器**。
> 这不是修饰 —— `scripts/build.py` 用 `sys.executable` 拉起 `idf.py`，
> 若那是系统 Python 就会报 `No module named 'rich_click'`，**看起来像 IDF 装坏了**。

**烧录与抓日志不受影响**（它们不需要 IDF 环境）：
`tools\boot-log.ps1`、`tools\flash-atzgauge.bat`、`tools\capture-boot.py` 照常可用。

### 铁律 ④：串口只有一处配置

| 优先级 | 来源 |
|---|---|
| 1 | 脚本参数 `-Port COM5` |
| 2 | 环境变量 `ATZ_PORT` |
| 3 | **`D:\AtzGauge\PORT.txt`** ← 换电脑只改这一个文件 |
| 4 | 兜底 `COM3` |

`PORT.txt` 不进 git，写一行 `COM3` 即可（无 BOM）。
本机实测：**COM3** 是设备，COM1 是主板。

### 铁律 ⑤：ESP-NOW 必须锁信道 1

主表把 ESP-NOW 信道**硬编码为 1**。**路由器 / 手机热点必须工作在信道 1**，
否则从表**一个包都收不到**（启动日志会直接告诉你跟的是哪个信道）。

### 铁律 ⑥：板型标识决定 OTA 通道，绝不能改

从表板型目录名 **`esp32-s3-touch-lcd-1.85-atzgauge`** 决定了 OTA 通道标识。
**改名会被官方固件静默覆盖**（OTA 认为自己不是同一个设备，或反之）。

### 铁律 ⑦：私密值放 `atz_local.h`，不进 git

| 项 | 值 |
|---|---|
| 路径 | `xiaozhi-esp32/src/main/boards/waveshare/esp32-s3-touch-lcd-1.85-atzgauge/atz_local.h` |
| 模板 | [`../开发参考/atz_local.h.example`](../开发参考/atz_local.h.example) |
| 内容 | 覆盖 `ATZ_DEBUG_TOKEN`（调试写接口的 `&key=` 口令） |
| 机制 | `atz_ui_config.h` **最前面**用 `__has_include` 探测并 include；默认值一律 `#ifndef` 兜底 |

> ⚠️ **`__has_include` 必须放在所有默认值之前**。写在文件末尾会报
> `'ATZ_DEBUG_TOKEN' redefined [-Werror]`，而本工程开了 `-Werror`，**整个构建直接失败**（缺陷 #40）。
>
> ⚠️ **口令必须轮换，不能只删文件**：旧口令明文已进 git 历史，删掉工作树那一行不会让它失效。

## 四、构建与烧录

### 从表（xiaozhi-esp32，IDF v6.1）

```powershell
# ① 上游源码若不存在，先拉（仓库不含上游，1.19 GB 太大）
git clone --depth 1 https://github.com/78/xiaozhi-esp32.git xiaozhi-esp32/src

# ② 打上本项目的改动（幂等，可重复跑）
cd xiaozhi-esp32/mods-atzgauge
node apply-mods.mjs      # 打补丁
node verify-mods.mjs     # 校验：全部改动就位

# ③ 编译（板型参数必须带厂商前缀，否则 build.py 报 not found）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\idf-run.ps1 `
    -Command "python scripts/build.py waveshare/esp32-s3-touch-lcd-1.85-atzgauge"

# ④ 烧录（别用 @flash_args，Windows 上引号传不过去）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\idf-run.ps1 `
    -Command "cmd /c tools\flash-atzgauge.bat"
```

```bash
# ① 先确认 build/ 不存在（上游误提交过，含 macOS 绝对路径，必须清除）
ls obd_brz_gauge/repo/build        # 应当报 No such file

# ② 编译

# ③ 只刷 app 分区（保留分区表 / bootloader / bootmedia / NVS 设置）

```

### 抓日志

### 主表补丁的位置（重要）

`obd_brz_gauge/repo/` 里我们的改动是**未提交**的工作树修改（7 个文件）。
一旦 `git checkout` 或被重新克隆就会**永久丢失**。为此已做两重保护：

1. **导出为文件**：`docs/patches/00-master-framerate.patch`（27 KB，`git apply` 可用）
2. 保留在工作树中，`cd obd_brz_gauge/repo && git status` 可直接看到这 7 个文件

**接手建议**：确认无误后，把这 7 个文件在 `repo/` 里正式提交一次，或纳入类似从表
`mods-atzgauge/` 的重打套件。
