# 小智AI 与 OBD 仪表 共存可行性分析

> 硬件：微雪 ESP32-S3-LCD-1.85（ESP32-S3R8 / 16MB Flash / 8MB PSRAM）
> 软件：小智AI（xiaozhi-esp32）+ OBD 仪表（obd_brz_gauge）
> 结论日期：本会话

---

## 一、先说结论

| 问题 | 答案 |
|---|---|
| 这块板能跑小智AI吗？ | ✅ **能，官方支持**。微雪文档明确 `ESP32-S3-LCD-1.85` 和 `ESP32-S3-Touch-LCD-1.85` **共用同一份固件**（v2.4.2） |
| 小智AI + 仪表能同时跑吗？ | ⚠️ **技术上能，但不建议现在做** |
| 性能够吗？ | CPU/PSRAM 够；**内部 SRAM、Flash、射频**三处吃紧 |
| 最大瓶颈 | ❌ **2.4G 射频共存**（WiFi + BLE 共用一个射频） |

## 二、官方支持情况（已验证）

- 微雪 [AI 应用教程](https://docs.waveshare.net/ESP32-S3-LCD-1.85/ESP32-AI-Tutorials/) 适配列表里**有** `ESP32-S3-LCD-1.85`，固件版本 v2.4.2
- 原文："部分型号的固件通用，例如 ESP32-S3-LCD-1.85 和 ESP32-S3-Touch-LCD-1.85 可使用同一固件。"
- [xiaozhi-esp32](https://github.com/78/xiaozhi-esp32) 仓库存在板型目录 `main/boards/esp32-s3-touch-lcd-1.85`
- 固件下载：https://github.com/78/xiaozhi-esp32/releases 或 https://github.com/waveshareteam/ESP32-AIChats/tree/master/xiaozhi-esp32

## 三、性能逐项体检

| 资源 | 判定 | 说明 |
|---|---|---|
| CPU（双核 Xtensa LX7 240MHz） | ✅ 够 | 需手动设置任务亲和性（core0 音频/AI，core1 UI/OBD），默认调度跑不好 |
| PSRAM 8MB | ✅ 够 | LVGL 双缓冲 360×360×2×2 ≈ 518KB；小智AI 唤醒词模型 + AFE + Opus 缓冲 |
| 内部 SRAM 512KB | ⚠️ 紧张 | WiFi 协议栈 + BLE 协议栈**必须占内部 RAM**，这是硬约束 |
| Flash 16MB | ⚠️ 很紧张 | 必须砍功能，见下 |
| **2.4G 射频** | ❌ **最致命** | WiFi 与 BLE 分时共用，无法回避 |

## 四、三个真正的坑

### 坑 1：射频共存（最致命，改不掉）

ESP32-S3 **只有一个 2.4GHz 射频**，WiFi 和 BLE 分时共用（Espressif 官方 [RF 共存文档](https://docs.espressif.com/projects/esp-idf/zh_CN/release-v5.0/esp32s3/api-guides/coexist.html)）。

- **小智AI**：WiFi 连云端，持续上传麦克风音频 + 下载 TTS，要求连续低延迟流
- **仪表**：BLE 连 Vgate，~10Hz 轮询 OBD，要求准时
- 后果：语音卡顿断字、OBD 丢包转速跳动
- 共存机制保证"都不断"，但**实时性必然下降**。这是硬件层分时，调优无法消除。

### 坑 2：Flash 16MB 装不下两套

| 项目 | 占用 |
|---|---|
| 仪表 bootmedia（开机动画） | 6.16MB |
| 仪表 theme 分区 | 4MB |
| 仪表 app | 2.26MB |
| 小智AI app | ~4MB |
| 小智AI 唤醒词模型 | ~2MB |

全要 = 远超 16MB。要合并**必须砍掉开机动画（省 6.16MB）和主题分区（省 4MB）**。

### 坑 3：整合是中级嵌入式工程

两边共用同一块屏（ST77916）和同一套音频硬件（MIC + PCM5101），因此必须：
1. 合并 BSP 层（显示、触摸、音频驱动只能有一套）
2. 重写自定义分区表
3. 统一 LVGL 版本（仪表用 LVGL 8，需与小智AI 对齐）
4. 手动分配任务到不同核心
5. 处理射频共存参数

**这是固件合并工程，不是改配置。**

## 五、三个方案对比

| | 方案 A：两块板 ⭐推荐 | 方案 B：一块板分模式 | 方案 C：真合并 |
|---|---|---|---|
| 做法 | 本板跑小智AI；另买 ESP32-S3 跑仪表 | 开机选"仪表/对话"模式 | 两个功能塞进一个固件 |
| 额外成本 | ¥0 ~ ¥85 | 0 | 0 |
| 稳定性 | 各自都稳 | 稳 | 射频共存打折 |
| 实现难度 | 几乎为 0 | 中 | 高（以月计） |
| 能否同时用 | ✅ 能 | ❌ 不能 | ✅ 但两边都打折 |

### 推荐：方案 A（分工原则 —— 贵板给仪表，便宜板给小智AI）

> ⚠️ **成本更正**：早先写的「¥30~50」是**裸板**价。带屏整板（如微雪 1.85）确实 ¥150~200。
> 但**仪表必须用微雪这块板**（obd_brz_gauge 的 ST77916 驱动是专为它写的，换板要重写显示驱动）；
> **小智AI 反而可以随便用便宜板**（官方支持 30+ 板型，含面包板方案）。

**便宜板跑小智AI（官方面包板方案，已确认）：**

| 部件 | 参考价 |
|---|---|
| ESP32-S3-DevKitC-1（**Flash ≥8MB、PSRAM ≥2MB**，推荐 N16R8） | ¥35~55 |
| INMP441 I2S 麦克风 | ¥5~8 |
| MAX98357A I2S 功放 | ¥5~8 |
| 8Ω 3W 喇叭 | ¥3~5 |
| 面包板 + 导线 | ¥5~10 |
| **合计** | **约 ¥55~85** |

- 接线（官方默认）：MAX98357 → LRC=GPIO4, BCLK=GPIO5, DIN=GPIO6；INMP441 → WS=GPIO10, SCK=GPIO11, SD=GPIO3
- ⚠️ INMP441 的 VDD/GND **不能接反，会烧毁麦克风**
- 代价：面包板方案**没有屏幕**（只有 RGB 灯指示），少了小智的表情界面

**分配结论：**
- **仪表 → 微雪 ESP32-S3-LCD-1.85**（必须，代码为它而写）
- **小智AI → 便宜 ESP32-S3 面包板方案**（¥55~85）或再买一块带屏板（¥150~200，有表情界面）

- **先走哪条都行，但最省钱的起步是：一块板来回刷（¥0）**，用一段时间确定自己到底更需要哪个，再决定要不要为第二个功能花钱。
