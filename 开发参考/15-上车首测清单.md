# 上车首测清单（阿特兹 × obd_brz_gauge）

> 目标：**一次上车把"能不能用"和"还差什么"全部搞清楚。**
> 原则：**所有操作停车做，别在开车时碰仪表。**

---

## 〇、出发前在家做完

### 1. 车型 profile 先设好（避免在车里手忙脚乱）

设备上：**设置页 → `VEHICLE` 滚轮 → 选 `MX-5 ND`**（`ui_ScreenPageSettings.c` 里就是这个名字）

**为什么先选 `MX-5 ND` 而不是 `OBD2 Generic`**：

| Profile | 机油温度走什么 | 对阿特兹合适吗 |
|---|---|---|
| `OBD2 Generic` | 标准 PID `01 5C`（°C = A−40） | ❌ **马自达不支持 01 5C** |
| **`MX-5 ND`** | **马自达 Mode 22 `1310`（主）/ `111F`（备）** | ✅ 唯一的马自达方案 |

`MX-5 ND` 的齿比/轮胎是 MX-5 的，**档位显示会不准**——那是预期的，不影响转速/水温/机油温度。

### 2. 软件就绪

- 双击 `D:\AtzGauge\tools\car-log.bat` 就能抓日志（自动找串口、自动存文件、掉线自动重连）
- 日志存到 `D:\AtzGauge\backup\car-log-<时间戳>.txt`

### 3. 硬件清单

| 带 | 说明 |
|---|---|
| **笔记本电脑** ⭐ | **首测强烈建议带**——既能给仪表供电，又能同时抓日志。`05` 号文档说"只带充电宝"是给**后续迭代**的建议，首测带电脑信息量大得多 |
| USB **数据线** | 能传数据的，不是纯充电线 |
| Vgate iCar Pro 2S | |
| 手机 | 拍视频记录 |
| 车充 / 充电宝（备用） | 笔记本没电时给仪表供电 |

**出发前把笔记本设成"接电源时永不睡眠 / 合盖不休眠"**，否则日志会断在半路。

### 4. ⚠️ 关掉手机上的 OBD App

**这是最容易踩的坑**：BLE ELM327 适配器通常**只允许一个中央设备连接**。
如果手机上的 **Car Scanner / Torque / Vgate 官方 App** 还连着 Vgate，仪表的 BLE SCAN 会看不到它，或者看得到但连不上。

**上车前把手机的蓝牙关掉，或至少退出所有 OBD App。**

唯一那条 BLE 连接（`41:42:86:9b:2e:7e`）是**手机**连的 RaceChrono 链路 —— 和 OBD 是两条独立链路，别混淆。

### 下次上车请务必按这个顺序

1. **手机蓝牙关掉**（本清单第 〇.4 节，最常见原因：Vgate 同时只接受一个中心设备）
2. 车通电 → 等仪表起来（约 2 秒）
3. 导航到 **BLE SCAN**（第 3 步的路径）→ **选中 Vgate → 按下连接**（不只是看一眼列表！）
4. 期望现象：屏幕转速表有反应（怠速约 700~800 rpm）+ 串口出现 `elm327_ble:` 开头的新日志
5. 日志要**覆盖整个操作过程**：`tools\boot-log.ps1 -Seconds 120`，别只抓开机那段

### 判断"卡在哪"的对照表（从固件里挖出来的真实日志串）

| 日志 | 含义 |
|---|---|
| `ble_scan_ui: Connecting: <名字>` | 连接尝试开始了（**没这条 = 根本没点连接**） |
| `Pairing failed, rescanning` | 配对失败，固件在重试 |
| `W Enable notify failed status=%d` | 连上了但通知没开起来 |
| `E FFF0/18F0/FF12 not found, using full range` → `E No characteristics found!` | 服务/特征发现失败（适配器不是标准 ELM327 GATT） |
| `W BLE disconnected during ELM init seq, aborting` | 连上后掉线（多半被别的中心抢了） |
| `W No valid OBD data >10s, re-init ELM (self-heal #N)` | 连上了但读不到数据，固件在自愈重试 |

> ★ **判断 OBD 通没通，只看一条：日志里有没有 `elm327_ble:`。** 别用"手机上看到设备名""列表里能扫到"当作通了。

## 一、到车上（严格按顺序）

### 第 1 步：插 Vgate（先别插仪表）

1. 找 OBD 口：阿特兹在**驾驶位方向盘左下方、踏板附近**
2. 插上 Vgate → **看指示灯亮不亮**
3. ⭐ **顺便做一个重要测试：OBD 口是不是常电**

   **阿特兹是一键启动，没有钥匙可拧**，用按钮循环断电：

   - **不踩刹车**，按 `Start` 按钮：第一下 → `ACC`，第二下 → `ON`，第三下 → **`OFF`**（全车断电）
   - 进到 `OFF` 后，**人留在车里别动**（别开门、别碰开关、别踩踏板）**等 15 分钟**
   - 看 Vgate 灯**是否还亮**

   | 结果 | 结论 |
   |---|---|
   | 灯灭 | OBD 口熄火断电 → 可以长期插着 ✅ |
   | 灯还亮 | **是常电** → **停车必须拔 Vgate**，否则耗电瓶 ⚠️ |

   > ⚠️ 别用"锁车后第二天再看"的办法——万一是常电，电瓶已经被耗了一晚。
   > ⚠️ **开门动作本身会唤醒部分电路**，所以要在开门前就把灯看清楚。
   > OBD 第 16 脚在不少车上是电瓶直供，这一条很多人栽过。

### 第 2 步：接仪表，开始抓日志

1. 笔记本用 USB 线接仪表
2. **双击 `tools\car-log.bat`**（先启动抓日志，再看屏幕，这样开机的日志也不会漏）
3. 等仪表开机完成

### 第 3 步：扫描并连接 Vgate

1. 仪表导航：**主界面 → 右滑到版本页（EasterEgg）→ 上滑 → BLE SCAN 页**
2. 看 `NEARBY` 列表里有没有 Vgate（名字一般是 `OBDII`，也可能带 `Vgate` / `iCar`）
3. **点它连接**
4. 日志里应出现 `elm327_ble: ... connected` 之类的行

> ### 📌 手动连一次，之后就是自动的（源码实测结论）
>
> 仪表**靠 MAC 地址精确匹配**来认设备，**完全不看名字**。源码里 `match_device_target()` 明写：
>
> ```c
> (void)target_name;   // 名字参数被显式丢弃，只用于界面显示
> // Only exact MAC matches: never auto-connect when no MAC is bound (no fuzzy name matching,
> // to prevent connecting to a nearby same-named adapter that yields no data).
> // The user must manually select and bind a MAC on the BLE SCAN page.
> if (!s_target_bda_valid) return false;
> return memcmp(pr->scan_rst.bda, s_target_bda, sizeof(esp_bd_addr_t)) == 0;
> ```
>
> | 阶段 | 行为 |
> |---|---|
> | **第一次（没绑定过）** | **必须手动** —— MAC 全零时 `s_target_bda_valid = false`，**绝不自动连任何设备**；而且没配过设备时**开机直接把你送到 BLE SCAN 页** |
> | **点选之后** | **自动** —— 点的那一下把 MAC 存进 NVS 的 `ble_obd_mac[6]`，之后每次开机按 MAC 精确重连 |
>
> ⚠️ **上车前先在 BLE SCAN 页把之前存错的设备删掉**（`SAVED DEVICE` 面板右边的 `×`），
> 免得它又自动连上错的东西。
>
> ⚠️ **实测记录（原因未定，勿套结论）**：曾经观察到一次它在**没有绑定 MAC** 的情况下
> 自动连上一台陌生 BLE 设备并空跑 `ATSP1~12`。
>
> **但不要再归因于"固件版本旧"** —— 查过提交历史：`elm327_ble_client.c` 的最后一次修改是
> 2026-08-26（`28a88020`），**早于**本机固件的构建点 2026-09-03（`9c3fa1b`）。
> 也就是说上面那段"没绑 MAC 就不自动连、只认精确 MAC"的代码**本来就在板子里**。
> 那次自动连接的真实原因**尚未确定**。
>
> 实践结论不变：**上车前先把 `SAVED DEVICE` 里存错的设备用 `×` 删掉，然后在车上手动点一次 Vgate。**

### 第 4 步：看协议探测结果 ⭐ 关键

日志里会依次跑 `ATSP1 ~ ATSP12`（每个约 6 秒，全部跑完约 1 分钟）。

| 期望 | 含义 |
|---|---|
| **`Protocol 6`** | ✅ ISO 15765-4 CAN 500k —— **阿特兹就是这个** |
| 探测失败但 `using fallback protocol 6` | ✅ **也能用**——回退值恰好就是阿特兹的协议 |
| 探测出别的号 | ⚠️ 记下来，回来分析 |

### 第 5 步：看数据 ⭐ 关键

打着车，看屏幕：

| 项 | 期望 |
|---|---|
| 转速 | 有数、跟仪表盘大致一致 |
| 车速 | 有数、跟仪表一致 |
| 水温 | 冷车时低、热车后 85~95°C 左右 |
| **机油温度** | **重点观察**——马自达 Mode 22，能不能读出来是这次的核心问题 |
| 档位 | MX-5 齿比，**预计不准**，属预期 |
| 电压 | 应在 13.5~14.5V（着车后） |

### 第 6 步：记录

- 手机**拍屏幕视频**（尤其机油温度那一页）
- 日志已自动存盘，不用管

### 第 7 步：收车前测一次重连

关车/拔 Vgate → 再开 → 看仪表能否**自动重连**（不用再手动扫）。
这一步验证的是真实用车场景（每次上车都要重连）。

## 二、故障决策树

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| BLE SCAN 里**看不到** Vgate | Vgate 没通电 / **被手机占用** | 确认灯亮；**退出手机上的 Car Scanner/Torque/Vgate App，或直接关手机蓝牙** |
| 看得到但连不上 | 已被占用 / 距离远 | 同上；把仪表靠近 OBD 口 |
| 连上了但日志全是 `Timeout` | 对端不是 ELM327 / 服务发现失败 | 日志里找有没有 `FFF0/18F0/FF12 not found` |
| AT 有应答但 PID 全是 `NO DATA` | 协议不对 / profile 不对 | 换 `OBD2 Generic` 再试一次；确认协议号是不是 6 |
| 标准数据（转速/水温）有，**机油温度没有** | 马自达 Mode 22 PID 不匹配 | 日志里看 `1310` / `111F` 哪个在失败 → **这正是要写 ATENZA profile 的理由** |
| 档位乱跳 | 齿比是 MX-5 的 | **预期行为**，不用管 |
| 屏幕出现 `NO SIGNAL` | 数据断流 | 查日志是不是 BLE 掉线了 |
