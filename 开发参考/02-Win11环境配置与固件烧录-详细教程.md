# Win11 首次上手：环境配置 + 固件烧录 详细教程

> 适用：微雪 ESP32-S3-LCD-1.85 + obd_brz_gauge 固件
> 系统：Windows 11，第一次接触 ESP32

---

## 0. 先搞清楚你有两条路（别一上来就装 ESP-IDF）

| | 路线 A：只烧固件 | 路线 B：编译环境 |
|---|---|---|
| 目的 | 先把仪表跑起来、上车测试 | 改代码（加马自达阿特兹车型） |
| 需要装 | Python + esptool（约 30MB） | ESP-IDF 工具链（2~3GB） |
| 耗时 | 约 20 分钟 | 约 1 小时（下载看网速） |
| 什么时候做 | **现在** | 路线 A 跑通之后 |

**结论：先走路线 A。** 大多数人卡在环境和编译上就放弃了，而烧现成固件根本用不到编译器。

---

## ⚠️ 开学前必须记住的两条铁律（Win11 特有坑）

### 铁律 1：所有路径必须是纯英文，不能有中文和空格

你现在的目录是 `D:\测试`（含中文）。**ESP-IDF / 编译工具链遇到中文路径会直接报错**，而且报错信息很难懂。

✅ 正确做法：
```
D:\gauge\obd_brz_gauge      ← 项目放这里
D:\esp                      ← ESP-IDF 装这里
```
❌ 错误：
```
D:\测试\obd_brz_gauge        ← 含中文，编译必挂
C:\Users\张三\Desktop\...    ← 用户名是中文，也会出问题
```

> **这条规则只管两样东西：① 项目放哪 ② ESP-IDF 装哪。**
> Python 装在哪、pip 把包装到哪，都**不用你操心也不用改**——pip 自己决定（通常在 `C:\Users\你的用户名\AppData\Local\Programs\Python\...\Lib\site-packages`）。
>
> 顺便检查你的 Windows 用户名：打开 `C:\Users\` 看文件夹名。
> - 是 `Administrator` 这类英文名 → 没问题，直接用
> - 是中文（比如 `C:\Users\测试`）→ 路线 A 烧录照样没问题，但**路线 B 装 ESP-IDF 时务必把安装路径手动改成 `D:\esp`**

### 铁律 2：USB 线必须是"数据线"，不是"充电线"

手机充电线很多只能供电、不能传数据。用这种线，电脑永远找不到串口。
- 优先用开发板原装线，或者你确认能传数据的线（比如能连手机拷文件的线）。
- 烧录失败第一个要怀疑的就是线。

# 路线 A：烧录预编译固件（先做这个）

## A1. 安装 Python

1. 打开 https://www.python.org/downloads/windows/
2. 下载 **Windows installer (64-bit)**（**3.10 及以上都行**；esptool 官方支持 3.10 / 3.11 / 3.12 / 3.13 / 3.14，**Python 3.13 完全没问题**）
3. 双击安装，**⚠️ 安装第一屏一定要勾选最下面那个 `Add python.exe to PATH`**，然后点 Install Now
   - 忘了勾也没事，重装一次或者手动加 PATH
4. 验证：按 `Win + R` → 输入 `cmd` → 回车，在黑窗口里输入：
   ```
   python --version
   ```
   出现 `Python 3.1x.x` 就成功了。
   - 如果提示"不是内部或外部命令"，说明 PATH 没配好，回去重装并勾选 Add to PATH。

## A2. 安装 esptool（烧录工具）

在刚才的 cmd 窗口里输入：

```
pip install esptool
```

**如果下载很慢或超时**（国内常见），换清华源：

```
pip install esptool -i https://pypi.tuna.tsinghua.edu.cn/simple
```

验证：

```
python -m esptool version
```

出现版本号（你的是 `esptool v5.4.0`）即成功。
> 说明：用 `python -m esptool` 这种写法，不管 PATH 有没有配好都能用，最稳。

> ⚠️ **esptool 5.x 的命令语法和 4.x 不一样！** 命令名从下划线改成了**连字符**：
> - `write_flash` → **`write-flash`**
> - `erase_flash` → **`erase-flash`**
>
> 用旧的下划线写法在 5.x 上会直接报 `invalid choice` 错误。
> 仓库自带 README 里的命令是按 esptool 4.x 写的，**必须按本文的写法改**。

## A3. 下载项目

**方法一（推荐，不用装 git）：**
1. 打开 https://github.com/steveEcode/obd_brz_gauge
2. 绿色 **`Code`** 按钮 → **`Download ZIP`**
3. 解压到 **纯英文路径**，例如 `D:\gauge\`，最终变成：
   ```
   D:\gauge\obd_brz_gauge\
   ```

**方法二（如果你装了 git）：**
```
cd /d D:\gauge
git clone https://github.com/steveEcode/obd_brz_gauge.git
```

> ZIP 下载得到的是默认分支 **`main`**，记住这一点，下面烧录地址要用。

## A4. 确认固件文件都在

打开资源管理器，进入：

```
D:\gauge\obd_brz_gauge\firmware\release\
```

应该能看到这几个文件：

| 文件 | 作用 |
|---|---|
| `bootloader\bootloader.bin` | 引导程序 |
| `partition_table\partition-table.bin` | 分区表 |
| `ota_data_initial.bin` | OTA 初始数据 |
| `obd_brz_gauge.bin` | **主程序固件** |
| `bootmedia.bin` | 开机动画（可选，可跳过） |
| `flash_address_map.txt` | **烧录地址表（以它为准）** |

**⚠️ 请打开 `flash_address_map.txt` 看一眼**，确认 `bootmedia.bin` 的地址是 `0x620000`（main 分支）还是 `0xA20000`（theme-upgrade 分支）。下面示例按 **main 分支 = 0x620000** 写。

## A5. 找到 COM 口（串口号）

1. 先用 USB 线把开发板连到电脑
2. 右键"开始"菜单 → **设备管理器**
3. 展开 **端口 (COM 和 LPT)**
4. 应该看到类似：
   ```
   USB 串行设备 (COM5)        或        USB Serial Device (COM5)
   ```
   记下这个 **COM5**（你的可能是 COM3、COM7…，以实际为准）

**如果看不到任何 COM 口：**
- 换一根 USB 线（最常见原因）
- 换电脑上另一个 USB 口（优先用主板后置 USB 口，别用前面板/扩展坞）
- 手动进入下载模式：**按住板上的 BOOT 键不松 → 插 USB → 松开 BOOT**
- 设备管理器里出现带黄色感叹号的未知设备 → 需要装 USB 驱动（ESP32-S3 原生 USB 一般 Win11 免驱；若你的板子是桥接芯片版，装 CH34x 驱动：https://www.wch.cn/downloads/CH341SER_EXE.html）

## A6. 擦除 Flash（首次烧录建议做）

把 `COM5` 换成你实际的串口号：

```
python -m esptool --chip esp32s3 -p COM5 erase-flash
```

看到 `Chip erase completed successfully` 就好。

> 为什么要擦？因为要清掉旧的 NVS 配置和残留固件，避免分区表不匹配导致白屏/反复重启。

## A7. 烧录固件（核心步骤）

**先把 cmd 切到项目目录**（`cd /d` 可以跨盘符切换）：

```
cd /d D:\gauge\obd_brz_gauge
```

然后执行（**整条命令是一行，直接复制**，`COM5` 换成你的）：

```
python -m esptool --chip esp32s3 -p COM5 -b 460800 write-flash --flash-mode dio --flash-freq 80m --flash-size 16MB 0x0 firmware/release/bootloader/bootloader.bin 0x8000 firmware/release/partition_table/partition-table.bin 0xf000 firmware/release/ota_data_initial.bin 0x20000 firmware/release/obd_brz_gauge.bin 0x620000 firmware/release/bootmedia.bin
```

**地址对照（main 分支）：**

| 地址 | 文件 |
|---|---|
| `0x0` | bootloader.bin |
| `0x8000` | partition-table.bin |
| `0xf000` | ota_data_initial.bin |
| `0x20000` | obd_brz_gauge.bin |
| `0x620000` | bootmedia.bin |

**正常输出长这样：**
```
Writing at 0x00020000... (100 %)
Wrote 2259792 bytes (...)
Hash of data verified.
Leaving...
Hard resetting via RTS pin...
```

烧完板子会自动重启，屏幕应该亮起来。

> **不想烧开机动画？** 把命令最后的 `0x620000 firmware/release/bootmedia.bin` 整段删掉即可，不影响使用。

## A8. 看运行日志（排查问题必备）

ESP-IDF 的 `idf.py monitor` 你用不了（没装 IDF），但可以用 miniterm：

```
python -m serial.tools.miniterm COM5 115200
```

- 退出：按 `Ctrl + ]`
- 如果提示缺 pyserial：`pip install pyserial`

正常应该能看到类似：
```
elm327_ble: OBD BLE connected
elm327_ble: Send 01 0C
```

## A9. 烧录阶段故障排查表

| 现象 | 原因 | 解决 |
|---|---|---|
| `could not open port COM5` | 串口号错 / 被占用 | 关掉其他串口工具；重查设备管理器 |
| 一直卡在 `Connecting...` | 没进下载模式 | 按住 BOOT 插 USB；或换 USB 线 |
| `Failed to connect` | 线是充电线 / 波特率太高 | 换数据线；把 `-b 460800` 改成 `-b 115200` |
| 烧录成功但屏幕全黑 | 背光/固件/分区不对 | 确认烧了 `bootmedia.bin` 且地址对；重跑 A6 擦除再烧 |
| 屏幕反复重启 | 分区表与固件分支不匹配 | 确认用的地址表和下载的分支一致 |
| 屏幕白屏 | bootmedia 地址错 | 打开 `flash_address_map.txt` 核对地址 |

## A10. 上车实测（烧录成功之后）

1. 把 **Vgate iCar Pro 2S** 插到车上的 OBD 口（方向盘下方）
2. 车辆通电（ACC 或启动）
3. 仪表开机 → 进 **BLE SCAN** 页面 → 找到 Vgate 设备名（通常叫 `IOS-Vlink`、`V-Link`、`Vgate` 之类）→ 连接
4. 设置里 **OBD 协议选 6**（ISO 15765-4 CAN@500K，阿特兹用的就是它）
   - 或者选 **0 = Automatic** 让它自己找（推荐第一次这么干）
5. 先选车型 **`OBD2 Generic`**，确认转速/车速/水温有数据
6. 有数据了再试 **`MX-5 ND`**（马自达，带 Mode 22 油温公式）

> 读不到数据？看 `D:\测试\开发参考\obd_brz_gauge\OBD_TROUBLESHOOTING.md`

# 路线 B：安装 ESP-IDF 编译环境（跑通路线 A 之后再做）

只有你要**改代码**（比如给阿特兹加专属车型 profile）时才需要。

## B1. 安装方式对比

| 方式 | 适合 | 说明 |
|---|---|---|
| **VSCode + Espressif IDF 插件**（推荐） | 新手 | 图形化，能点按钮编译烧录 |
| Espressif IDF 离线安装包 | 网络差 | 一次性下载完，自带所有工具 |
| 命令行在线安装 | 老手 | `install.bat` 那套 |

## B2. VSCode + Espressif IDF 插件（详细步骤）

### 1) 装 VSCode
- https://code.visualstudio.com/ 下载安装，一路默认（路径保持英文）

### 2) 装插件
- VSCode 左侧点**扩展**图标（四个方块）→ 搜索 **`Espressif IDF`** → 认准发布者 **Espressif Systems** → Install

### 3) 配置 ESP-IDF
- 按 `Ctrl + Shift + P` → 输入 **`ESP-IDF: Configure ESP-IDF Extension`** → 回车
- 选择 **`EXPRESS`**（快速安装）
- **下载服务器选 `Espressif China`**（国内下载快很多，别选 GitHub）
- ESP-IDF 版本选 **`v5.5.x`**（仓库用的 5.5.3）
- **安装路径改成 `D:\esp`**（⚠️ 绝对不能用中文路径！）
- 点 Install，等 20~40 分钟（会下载 Python、工具链、ESP-IDF 源码）

### 4) 验证
- 装完后按 `Ctrl + Shift + P` → `ESP-IDF: Show ESP-IDF Installation Manager` 或直接看底部状态栏有没有 IDF 版本号

## B3. 打开项目并编译烧录

1. VSCode → `File` → `Open Folder` → 选 **`D:\gauge\obd_brz_gauge`**（含 `CMakeLists.txt` 那一层）
2. 底部状态栏选择串口（COM5）和 target **esp32s3**
3. 打开 IDF 终端（`Ctrl + E` 然后 `D`，或点状态栏终端图标），执行：

```
idf.py set-target esp32s3
idf.py build
idf.py -p COM5 flash monitor
```

- 退出 monitor：`Ctrl + ]`
- 第一次 build 很慢（10~30 分钟），之后就快了

**或者直接用界面按钮**：底部状态栏的火苗图标 🔥 = Build → Flash → Monitor 一键完成。

## B4. 编译环境的 Win11 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 编译报一堆路径错误 | 路径含中文/空格 | 项目移到 `D:\gauge`，IDF 装 `D:\esp` |
| 下载工具链卡住 | 用了 GitHub 源 | 重装时选 `Espressif China` |
| `idf.py: command not found` | 没激活 IDF 环境 | 用 VSCode 的 IDF 终端；或运行 ESP-IDF PowerShell 快捷方式 |
| 病毒软件拦截 | Defender 扫描编译产物 | 把项目目录和 `D:\esp` 加入排除项（能明显加速） |
| 路径太长报错 | Windows 260 字符限制 | 项目路径尽量短（`D:\gauge\...`） |
| 报警告 `CMake Warning` 但仍能继续 | 正常 | 只要最终 `Project build complete` 就行 |

## B5. 烧录后想改马自达配置？

看这份：`D:\测试\开发参考\obd_brz_gauge\VEHICLE_CONFIG.md`
给阿特兹加车型只需改 2 个文件：
- `main/app_obd_dsp/vehicle_profiles.c`（传动比、轮胎半径）
- `main/app_obd_dsp/vehicle_custom_config.h`（油温公式、协议锁定）
