# 自定义主题与开机动画（不用装 ESP-IDF 的路线）

> 适用固件：`main-104-9c3fa1b27e9d`（2026-09 实测）
> 结论：**做主题只要「画图 → 打包 → 烧 0x620000」，全程不需要 ESP-IDF、不需要手机 App。**

---

## 一、先搞清两套主题机制（关键）

主题有**两条完全独立的路径**，别搞混：

| | ① 编译进固件（内置主题） | ② **`theme_0` 分区（打包主题）** |
|---|---|---|
| 源文件 | `themes/<id>/theme.toml` | `theme_manifest.json` + `assets/` + `layout.json` |
| 打包工具 | `tools/gen_themes.py`（CMake 构建时自动跑） | `tools/theme_packer/pack_theme.py` |
| 产物 | `ui_theme_generated.c` → 编进固件 | **独立 4MB blob（`theme.bin`）** |
| 如何生效 | `idf.py build flash` | **直接烧 `0x620000`** 或 App/HTTP 上传 |
| 要 ESP-IDF？ | **要** | **不要** ✅ |
| 选择方式 | 设置 → THEME 滚轮（存槽位号到 NVS） | 开机自动优先加载 |

**优先级**：开机先试 `theme_0`，解析失败才回退内置默认。日志里这两行就是证据：

```
I (1673) theme_engine: Loading theme from theme_0
I (1700) theme_engine: Theme 'TURBO PRO' v1.0.0 loaded successfully
I (1820) ui: Custom theme detected - skipping built-in gauge pages to save RAM
```

> 注意最后一行：**检测到自定义主题时，内置仪表页会被跳过以省 RAM。** 所以烧了主题后页面构成会变。

## 二、自己画一套主题（四步）

### 第 1 步 · 建目录

```
D:\AtzGauge\mytheme\
  theme_manifest.json     必需
  assets\ring.png         可选 · 正好 360×360 · 带透明（中间镂空）
  assets\dial.png         可选 · 正好 360×360 · 最底层，透明忽略
  assets\needle.png       可选 · ≤360×360 · 带透明 · ⚠️ 必须画成朝右
  layout.json             可选 · 自定义 main_gauge 页布局（进阶）
```

参考素材：`obd_brz_gauge\src\themes\_TEMPLATE\assets\` 里有三张**尺寸和朝向都正确**的现成 PNG，复制过去照着改。

### 第 2 步 · 填 `theme_manifest.json`

⚠️ 是 **JSON**，颜色是**字符串** `"0xRRGGBB"`（不是 TOML 数字）。

```json
{
  "schema_version": "1.0",
  "theme": {
    "id": "myskin", "name": "MYSKIN", "version": "1.0.0",
    "author": "you", "description": "一句话描述"
  },
  "colors": {
    "bg": "0x0A0A0A",
    "ring": "0xFF6B00",
    "arc_track": "0x2A2A2A",
    "arc_indicator": "0xFFFF00",
    "text_primary": "0xFFFFFF",
    "text_secondary": "0x888888",
    "needle": "0xFF3030",
    "panel": "0x1A1A1A"
  }
}
```

8 个颜色角色全部必填：

| 角色 | 用在哪 |
|---|---|
| `bg` | 屏幕/页面背景（一般用很深的颜色，亮底夜里晃眼） |
| `ring` | 每个页面边缘的外圈表框 |
| `arc_track` | 弧线底轨、滑块凹槽、小刻度（"还没走到"） |
| `arc_indicator` | 弧线进度、滑块填充和滑块头（"已走到"）**要明显比 arc_track 亮** |
| `text_primary` | 数值、主文字（大号数字） |
| `text_secondary` | 提示文字、单位、小标签（比 primary 暗，但开车瞄一眼要看得清） |
| `needle` | 指针页的指针 |
| `panel` | 面板/列表/滚轮背景 |

### 第 3 步 · 打包

```cmd
pip install Pillow
python D:\AtzGauge\obd_brz_gauge\src\tools\theme_packer\pack_theme.py D:\AtzGauge\mytheme D:\AtzGauge\mytheme\theme.bin
```

产物**正好 4,194,304 字节**（`PARTITION_SIZE = 4*1024*1024`，必须与 `theme_0` 分区一致）。

### 第 4 步 · 烧录

```cmd
python -m esptool --chip esp32s3 -p COM3 write-flash --flash-mode dio --flash-freq 80m --flash-size 16MB 0x620000 D:\AtzGauge\mytheme\theme.bin
```

写入区间是 `0x620000 ~ 0xA1FFFF`，**正好顶到 `0xA20000` 的 bootmedia 之前**，不会互相踩。

## 三、主题的五条硬约束

1. **素材必须正好 360×360**（`ring` / `dial`）；`needle` 任意尺寸但不超过 360×360。尺寸不对 `pack_theme.py` 直接抛错。
2. **指针必须画成朝右（东）**。LVGL 绕 pivot 旋转，角度 0 = 原样绘制，画成朝上会整体偏 90°。`needle_pivot_x/y` 是旋转中心在图里的像素坐标（指针根部轴心）。
3. **语义色改不了**：`UI_SEM_ALERT`(0xFF4D4D) / `UI_SEM_FLASH`(0xFF0000) / `UI_SEM_ON`(0x06D6A0) / `UI_SEM_WARN`(0xFFD166) 全局固定。**装了车，红必须永远意味着"出事了"**——这是刻意设计。
4. **只换皮不换布局**：元素位置、字号、页面排布不在主题范围内（除非用 `layout.json` 自定义 `main_gauge` 页）。
5. **颜色显示会变**：360×360 屏是 RGB565，`0x0A0A0A` 实际显示成 `0x080808`、`0xFF6B00` → `0xFF6900`。这是色深决定，正常。

> 打包主题的素材**只占 theme_0 分区**。而编译进固件的主题素材会**无条件链接全部已注册主题**（单独一套约 645KB，总预算 1536KB）——这也是走打包路线的另一个理由。

## 五、开机动画

### 走 App（推荐）

配套 App 的「开机动画」页支持**手机本地抽帧编码**（`视频裁切和 boot_block 编码都在手机本地完成`），
操作项：选择视频 → 开始/结束时间 → 帧率 → 缩放 → 上下裁切 → **生成开机动画包** → 连接设备后上传。

产物是 `boot_block.txt`（清单）+ `boot_block.bin`（数据），设备端只保留**一个**活动槽位。

### ⚠️ 两个坑

1. **顺序**：先在**正常网络**下把包生成好（有些素材 App 要从服务器拉），**再**连仪表热点上传。
   原因：仪表热点没有外网，但它对 `/generate_204` 和 `/connectivity-check` 都回 **204**，
   会让 Android 误判"这个 WiFi 能上网"，把流量全走热点 → 下载必然失败。
2. **画布 360×360、比例 1:1**；圆屏四角会被裁掉，建议开圆形预览遮罩。

### 为什么值得做

当前固件**没有开机动画**，日志一直报：

```
W (2933) boot_block: manifest load failed: /bootmedia/boot_block.txt
```

上传一次动画包就会写入 `bootmedia` 分区的 manifest，警告消失、开机能播动画。

## 六、文档漂移清单（2026-09 实测勘误）

仓库文档与发布固件不同步，以下是**实测确认**的偏差，照着本文和 `08` 做，别照着上游文档做：

| # | 位置 | 文档写的 | **实测实际** |
|---|---|---|---|
| 1 | `firmware/README.md` main 表 | bootmedia `0x620000` | **`0xA20000`**（`0x620000` 已是 4MB 的 `theme_0`） |
| 2 | `docs/APP_INTEGRATION.md` | WiFi 密码 `obd2024` | **`88888888`**（源码 `#define OTA_WIFI_PASSWORD "88888888"`） |
| 3 | `docs/APP_INTEGRATION.md` | 主题上传「theme-upgrade 分支 only」 | main 固件**已有** `/ota/theme*` 全部路由 |
| 4 | 仓库 `android_app/app-debug.apk` | — | **落后**：只有 总览/固件升级/开机动画/设置 四个 tab，**没有主题刷入**；发布服务器上也没有 APK |
| 5 | `docs/APP_INTEGRATION.md` | `/ota/status` 无特殊说明 | 需要 `X-OTA-Token` 头；**免鉴权的是 `GET /ota/discover`**（返回 token）和 `GET /ota/info` |
| 6 | main 源码 `match_device_target()` | "never auto-connect when no MAC is bound" | 实测固件**会**自动连上一台陌生 BLE 设备并空跑 AT 命令 |

**排查这类问题的通用方法**：设备端每个接口一进门就 `ESP_LOGI`，日志里**没有**那条记录，
就说明请求根本没到设备——问题在客户端，不在设备。

## 七、命令速查

```cmd
:: 烧主题（4MB blob）
python -m esptool --chip esp32s3 -p COM3 write-flash 0x620000 <theme.bin>

:: 只读看设备身份
python -m esptool --chip esp32s3 -p COM3 flash-id

:: 抓启动日志（掉线自动重连）
python D:\AtzGauge\tools\serial-watch.py COM3 15
```

OTA 热点（设备进 OTA Mode 页时）：

| 项 | 值 |
|---|---|
| SSID | `OBD-Gauge-OTA-XXXX`（XXXX = AP MAC 后两字节，如 `9A05`） |
| 密码 | `88888888` |
| 网关 | `192.168.4.1` |
| 免鉴权接口 | `GET /ota/discover`（含 token）、`GET /ota/info`（设备清单） |
| 需 token 接口 | `GET /ota/status`、`POST /ota/firmware`、`POST /ota/bootmedia`、`POST /ota/theme` |
