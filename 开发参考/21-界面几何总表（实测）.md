## 一、坐标体系（先统一语言）

> ★★ **圆屏排版只有一条硬规则，但它必须按"四角"判**：
> 元素矩形 (x1,y1)-(x2,y2) 的**四个角**到圆心 (179.5,179.5) 的距离都要 **< 180**（留 4px 余量则用 176）。
> ⚠️ 只检查"最宽那一行的可用宽度 = 2√(180²−dy²)"是**不够的** —— 我就这么漏掉了 9 处出圆（缺陷 #31）。
>
> 给定一个元素的宽高，可用下面这段穷举出"哪些 y 放得下"（改布局前先跑一遍）：
>
> ```powershell
> function Sol([int]$w,[int]$h,[double]$m=176.0){
>   $x1=(179.5-$w/2); $x2=$x1+$w-1; $ys=@()
>   for($y=0;$y -le (360-$h);$y++){
>     $yb=$y+($h-1); $worst=0.0
>     foreach($cx in @($x1,$x2)){foreach($cy in @($y,$yb)){
>       $d=[math]::Sqrt([math]::Pow($cx-179.5,2)+[math]::Pow($cy-179.5,2))
>       if($d -gt $worst){$worst=$d}}}
>     if($worst -le $m){$ys+=$y}}
>   if($ys.Count -eq 0){"无解"}else{"y ∈ $($ys[0])..$($ys[-1])"}
> }
> Sol 168 31     # 例：168×31 的卡片
> ```
>
> 复核整页：把 `/layout` 抓下来，对每个**可见**控件（父级带 HIDE 的整棵子树跳过）算四角，
> 超过 180 就报出来。两页现在的结果是 **文字控件 0 出圆**。

| 说法 | 含义 |
|---|---|
| **屏幕坐标** | 左上角为 (0,0)，右下角为 (359,359)。表里 `(x1,y1)-(x2,y2)` 用的就是它 |
| **屏幕中心** | (180, 180) —— 圆屏的圆心，圆形屏上"居中"就是居到这个点 |
| **相对中心的偏移** | 代码里很多地方用 `lv_obj_align(obj, LV_ALIGN_CENTER, dx, dy)`，`dy=-100` 表示"比中心高 100px" |
| **圆形屏可视宽度** | 离中心 `dy` 的水平线上，只有 `2·√(175²−dy²)` 是能看见的（R 取 175，留 5px 余量） |
| 1 个 `spacing` 单位 | 主题里固定 = 2px（上游 LvglTheme 内部写死，改不了） |

## 四、三个"自己叠上去"的层（最容易改坏的地方）

### 4.1 转速环 `g_arc`（`atz_rpm_ring.cc`）—— **当前已停用**（2026-09-17）

> ★★ **2026-09-17 用户实测后要求删除**："换挡提示灯删除掉吧、转速环也删除掉"。
>   `ATZ_RPM_RING_ENABLE = 0` → 环与细环**都不再创建**，代码整块编译不进固件；
>   语音工具 `self.ui.set_rpm_ring` 与 `/ring` 的写参数也一并删除（`/ring` 现在只回
>   `ring compiled_in=0`，用来确认固件里到底有没有环）。下面是它的设计留档，改回 1 即恢复。

> ★ **按 obd_brz_gauge 的转速页设计**（`src/screens/ui_ScreenPageRpm.c`）：
>   **外沿一圈 10px 细环（bezel）+ 内侧一圈 340×340 / 20px 的转速弧**，
>   底槽压暗、指示弧用主题色、直角端头、无旋钮。
>   · LVGL 的弧是"从对象半径往内画"，所以细环直径取 **360** 才能贴死屏幕边（占半径 170~180），
>     转速弧 340 则占半径 150~170 —— 两者相邻而不相交，正是参照物的"外细内粗"。
>   · 两个对象都带 `LV_OBJ_FLAG_FLOATING`：**对象比屏幕大/贴边时，不加这个标志会把屏幕撑出滚动条**
>     （用户报的"环上一条小白条"就是它，见缺陷 #21）。
>   · 用户明确不要"内侧红区刻度"，已删除；红线靠 6500 转后指示弧变红来表达。

| 项 | 值 | 说明 |
|---|---|---|
| ① 外沿细环 | 直径 **360**、线宽 **10**、满不透明 | `ATZ_RPM_RING_BEZEL_*`；颜色 `ATZ_RPM_RING_BEZEL_COLOR`（0 = 主题文字色） |
| ② 转速弧 | 直径 **340**、线宽 **20**、**直角** | `ATZ_RPM_RING_D` / `_W` / `_ROUNDED`（改 1 = 圆头） |
| 弧底槽 | 主题色压到 70/255 | `ATZ_RPM_RING_TRACK_COLOR` / `_TRACK_OPA` |
| 指示弧基色 | 跟随主题文字色 | `ATZ_RPM_RING_BASE_COLOR`（浅底建议 `0x0A84FF`） |
| 满圈 / 变色 | 8000 rpm；5500 琥珀、6500 红 | `ATZ_RPM_RING_MAX_RPM` / `_WARN_RPM` / `_ALARM_RPM` |
| 节奏 | 100ms 取数 + **6ms** 插值 | 扫掠实测 **82~83 fps**，空闲 0 帧 |
| 死区 | 目标差 <20 rpm 不换目标；显示差 <4 rpm 不重绘 | 静止时 **0 帧/秒** |
| 开关 | ~~语音 / `/ring?enabled=0`~~ → 现在只有编译期 `ATZ_RPM_RING_ENABLE` | 环已删 |
| 换挡提示灯 | **已整块删除**（`ATZ_SHIFT_*`、NVS 键 `shift_rpm`、语音工具一起移除） | 车上本来就有换挡灯 |

> ★ **教训（缺陷 #23 的兄弟问题）**：这类统计/回调**不要寄生在"可能被关掉的功能模块"里**。
>   环里原本还带着 `/perf` 的帧率统计，环一关 `/perf` 就静默变全 0 —— 现在统计住在
>   独立的 `atz_perf.cc`，由 `AtzLcdDisplay::SetupUI()` 初始化，与任何 UI 功能解耦。

## 六、怎么自己重新量一遍（三步）

```text
1) 看当前几何：   http://<设备IP>:8099/layout           ← 控件树 + 每个控件的真实坐标
                                                          （末尾 "# end of tree" = 输出完整）
2) 看尺寸/字号：   http://<设备IP>:8099/size             ← 表情框、时钟字体与 line_height
3) 看流畅度：      http://<设备IP>:8099/perf             ← 帧率、单帧耗时、每帧重绘像素
   看点击区：      http://<设备IP>:8099/touch?seconds=8  ← 边点边看：落点坐标 + 命中区矩形
   模拟点击：      http://<设备IP>:8099/tap?x=&y=&key=   ← 不碰硬件，验证按钮回调链
```
