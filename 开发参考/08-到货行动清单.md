## ⚠️ 第 0 步（最重要）：开箱先确认是触摸版还是非触摸版

### 为什么重要

微雪两块板外观几乎一样，型号不同：

| 型号 | 触摸 | 仪表项目可用？ |
|---|---|---|
| `ESP32-S3-Touch-LCD-1.85` | ✅ 有 | ✅ 直接可用 |
| `ESP32-S3-LCD-1.85` | ❌ 无 | ⚠️ UI 无法导航，需改造 |

`obd_brz_gauge` 的界面**依赖触摸**（进 BLE 扫描页、选车型、进设置、调参数全靠触摸），
仓库里有 CST816 触摸驱动就是这个原因。

### 确认方法（按可靠性排序）

1. **看包装盒 / 板子丝印的型号**：含 `Touch` 就是触摸版
2. **看淘宝订单**的规格选项里有没有"触摸"
3. **跑微雪官方 Demo**：烧 `ESP32-S3-LCD-1.85-Demo.zip`，试触摸有无反应
4. （进阶）I2C 扫描：触摸版能在地址 `0x15` 扫到 CST816 芯片
   > ⚠️ **必须扫对总线**。微雪现行文档把触摸放在**独立 I2C 总线**（`TP_SDA=GPIO1` / `TP_SCL=GPIO3`），
   > 而 GPIO10/11 那条线上挂的是 RTC（`0x51`）和 IMU（`0x6A`）。
   > 在 GPIO10/11 上扫不到 `0x15` **不能**推出"非触摸版"——以官方 Demo 的触摸反应为准。

### 如果不是触摸版怎么办

| 方案 | 说明 |
|---|---|
| A. 售后换货 | 最省事，趁早 |
| B. 改代码用按键 | 微雪官方 Demo 有"BOOT+PWR 两键模拟触摸"的变通做法可参考；需改造 obd_brz_gauge 的 UI 交互 |
| C. 换项目 | 用只靠按键的项目重做 |

### 1.3 确认固件文件齐全

`D:\AtzGauge\obd_brz_gauge\firmware\release\` 下应有：

| 文件 | 作用 |
|---|---|
| `bootloader\bootloader.bin` | 引导程序 |
| `partition_table\partition-table.bin` | 分区表 |
| `ota_data_initial.bin` | OTA 初始数据 |
| `obd_brz_gauge.bin` | **主程序** |
| `bootmedia.bin` | 开机动画（可选） |
| `flash_address_map.txt` | **地址表（以它为准）** |

### 1.4 核对烧录地址

打开 `flash_address_map.txt`，确认地址（**当前 main 分支实测值**）：

| 地址 | 文件 |
|---|---|
| `0x0` | bootloader.bin |
| `0x8000` | partition-table.bin |
| `0xf000` | ota_data_initial.bin |
| `0x20000` | obd_brz_gauge.bin |
| `0xA20000` | bootmedia.bin |

> ⛔ **`0x620000` 已经不是 bootmedia 了，别再用。**
> 主题分区系统合入后（release 的 build tag 为 `feature/theme-partition-system-*`），
> `0x620000` 变成 4MB 的 `theme_0` 分区，bootmedia 被推到 `0xA20000`。
> 往 `0x620000` 烧 bootmedia = 写进主题分区 → 开机动画丢失/白屏。
>
> ⚠️ `firmware/README.md` 里的 "main branch" 地址表**仍是旧的 `0x620000`**，不可信。
> **以仓库根目录 `partitions.csv` + `flash_address_map.txt` 为准**（两者一致）。

## 第 2 步：插上电脑，找 COM 口

1. USB 线连接板子和电脑
2. 右键开始菜单 → **设备管理器** → 展开 **端口 (COM 和 LPT)**
3. 应该看到 `USB 串行设备 (COM5)` 之类，**记下号**

**看不到 COM 口？**
- 换一根 USB 线（最常见原因）
- 换主板后置 USB 口
- 按住板上 **BOOT** 键再插 USB，进入下载模式

---

## 第 3 步：验证通信（只读，不写数据）

```cmd
python -m esptool --chip esp32s3 -p COM5 flash-id
```

正常输出：
```
Chip is ESP32-S3 (QFN56) (revision v0.2)
Detected flash size: 16MB
```

✅ 看到这个说明线好、口对、通信正常 → 可以烧了

---

## 第 4 步：擦除 Flash

```cmd
python -m esptool --chip esp32s3 -p COM5 erase-flash
```

看到 `Chip erase completed successfully` 即成功。

> ⚠️ esptool 5.x 用**连字符**：`erase-flash` / `write-flash`（不是下划线）

---

## 第 5 步：烧录固件

先切到项目目录：

```cmd
cd /d D:\AtzGauge\obd_brz_gauge
```

然后（整条复制，`COM5` 换成你的）：

```cmd
python -m esptool --chip esp32s3 -p COM5 -b 460800 write-flash --flash-mode dio --flash-freq 80m --flash-size 16MB 0x0 firmware/release/bootloader/bootloader.bin 0x8000 firmware/release/partition_table/partition-table.bin 0xf000 firmware/release/ota_data_initial.bin 0x20000 firmware/release/obd_brz_gauge.bin 0xA20000 firmware/release/bootmedia.bin
```

**不想烧开机动画**？删掉最后 `0xA20000 firmware/release/bootmedia.bin` 即可。

## 常见问题速查

| 现象 | 原因 | 解决 |
|---|---|---|
| `could not open port COM5` | 串口号错/被占用 | 关掉其他串口工具，重查设备管理器 |
| 卡在 `Connecting...` | 没进下载模式 | 按住 BOOT 插 USB |
| `Failed to connect` | 充电线 / 波特率太高 | 换数据线；`-b 460800` 改 `-b 115200` |
| `invalid choice: 'write_flash'` | 用了 esptool 4.x 语法 | 改用连字符 `write-flash` |
| 屏幕黑/白/反复重启 | 分区或地址问题 | 重做擦除 + 烧录，核对 `partitions.csv` + `flash_address_map.txt`（**别信 `firmware/README.md` 的 main 表**） |
