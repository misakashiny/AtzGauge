# 19 · 与原版小智AI的差异对照（AtzGauge 从表版）

> **基线**：官方 `78/xiaozhi-esp32` **v2.5.0**
> **数据来源**：`xiaozhi-esp32\mods-atzgauge\manifest.json`（由 `tools\gen-mods-kit.mjs` 自动比对生成，不是回忆）
> **实测日期**：2026-09-15 凌晨

---

## 一、一句话结论

> 原版小智 = **联网的语音助手**。
> 本版 = **在完整保留原版能力的前提下**，把它变成"**能读车况、会主动报警、按键就能说话**"的车载从表。
> 相对上游只动了 **2 个文件（3 处连续块）**，其余 **17 个文件全是新增**。

---

## 二、功能对照表

### 2.1 原版就有、本版**完整保留**的

| 能力 | 说明 |
|---|---|
| 云端语音问答（LLM + TTS） | 协议、音频链路、状态机**一行未改** |
| 配网 / 激活 / OTA | 保留；但走**独立板型通道**（见 2.4） |
| BOOT 键单点 = 开始/结束对话 | 保留（所以即使没有触摸也能用） |
| 表情、字幕、通知、低电提示 | 保留 |
| MCP 工具框架 | 保留，并在其上**新增**了两个工具 |
| 亮度控制（`self.screen.set_brightness`） | 保留 |

### 2.2 本版**新增**的能力

| 能力 | 原版 | 本版 | 当前状态 |
|---|---|---|---|
| **读车辆数据** | 无（硬件路径都没有） | ESP-NOW 收主表 10Hz 广播：转速、车速、水温、油温、进气温度、负荷、节气门、电压、油压、空燃比 | ✅ 生效 |
| **主动阈值告警** | 无 | 水温 / 油温 / 转速 / 电压四类，**本地预录音频**（不依赖网络，车上有网没网都能响） | ✅ 生效 |
| **语音问车况** | 无 | MCP 工具 `self.car.get_status`：问"水温多少"能答；没数据会**明说没数据**而不是编 | ✅ 已注册 |
| **链路诊断** | — | 区分"信道不对"与"主表没开"（外来帧计数 + 方向性结论） | ✅ 生效 |
| **台架自检** | 无 | 启动打印三行 `SELF-TEST PASS`（收包→解析→缓存、规则引擎→告警音） | ✅ 生效 |
| **触摸唤醒对话** | 无（官方 1.85 板型**没有**触摸代码） | 点屏 = 开始对话（仅空闲时；AI 说话时点屏不打断） | ⚠️ 代码就绪，**硬件不应答已自动禁用** |
| **主界面车况常显条** | 无 | 水温/转速/电压常显在表情下方，无数据自动隐藏 | 🔶 已实现，**当前关闭** |
| **车机主题包** | 只有 light/dark | `atz-night`（座舱夜间）/ `atz-day`（白天高对比）/ `atz-amber`（琥珀夜间），**语音可切、掉电不丢** | 🔶 已实现，**当前关闭** |
| **本机截图端点** | 无 | `http://<设备IP>:8099/shot.jpg`、`/health`、`/theme?name=`、`/carbar?seconds=`、`/touch`、`/carpage?action=` | ✅ 生效（调试用，可一行关闭） |
| **「车况」整屏页面** | 无 | 语音「显示车况」进入：转速/车速（大号）+ 水温/油温/进气/负荷/节气门/电压/油压/空燃比 + 链路状态；超限变色；无数据整页变灰并提示。BOOT 键或语音「关掉车况」退出 | ✅ 生效（**独立于 `ATZ_UI_ENABLE`**，官方界面下同样可用） |

> 🔶 = 由 `atz_ui_config.h` 的 `ATZ_UI_ENABLE` 控制，**当前是 0（官方原版界面）**。
> 改成 1 重新编译即可启用，代码不用回滚。

### 2.3 观感上的差异（即使什么都不开也存在）

| 项 | 官方 1.85 | 本版 | 为什么 |
|---|---|---|---|
| 表情素材 | `noto-color-emoji_64`（64px） | **`noto-color-emoji_128`（128px）** | 1.85" 圆屏上 64px 显得又小又空；128px 是原始素材，不是拉伸 |
| 文字/图标字号 | 16px | **20px** | 车内观看距离下 16px 偏小 |
| 代价 | 资产分区约 1.26MB | 约 1.75MB（分区共 8MB） | 完全够用 |

### 2.4 ★ 最关键的一条：**独立板型 = 独立 OTA 通道**

| | 官方 1.85 板型 | 本版 |
|---|---|---|
| 板型标识 | `esp32-s3-touch-lcd-1.85` | **`esp32-s3-touch-lcd-1.85-atzgauge`** |
| 引脚 | —— | **与官方逐字节一致**（一个都没改） |
| 后果 | 官方 OTA 推送会**静默覆盖**成官方固件（我们的从表功能全没） | 走自己的通道，**不会被覆盖** |

> 这是照 `AGENTS.md` 的要求做的：`Never alter an existing board's pins to support different
> hardware. Add a uniquely named board or release variant; board identity affects OTA compatibility.`

## 四、为什么这么设计（几个关键取舍）

| 决定 | 原因 |
|---|---|
| **另起板型而不是改官方 1.85** | 板型标识决定 OTA 通道；沿用官方名会被官方固件静默覆盖 |
| **从表不初始化 WiFi** | 小智的 WiFi 由 WifiBoard 掌管（要连路由器上云）；ESP-NOW 跟随 STA 信道即可 |
| ↳ 由此推出的**硬约束** | 主表把信道硬编码为 **1** → **路由器/热点必须工作在信道 1**，否则从表一个包都收不到（启动日志会直接告诉你） |
| **告警用本地预录音频** | 车上可能没网；安全相关提示不能依赖云端 TTS |
| **阈值加迟滞 + 30s 节流 + 2s 陈旧门控** | 防误报：越线才报、回落才解除；同一告警最短 30s 再出声；主表 2s 无数据则整体静默，**绝不拿过期值报警** |
| **UI 定制走"叠加 + 主题注册"而不是改上游** | 上游升级后我们这层大概率照样生效（只依赖 `lv_screen_active()` 与主题对象） |
| **代码放板型目录** | 该目录由 `file(GLOB BOARD_SOURCES ...)` 自动收集 → **新增文件不必改上游 CMakeLists** |

## 五、当前**未生效**或**未验证**的

| 项 | 状态 | 说明 |
|---|---|---|
| **触摸唤醒对话** | ⚠️ 未生效 | CST816S **完全不应答 I2C**（两条总线、两种 API、复位脉冲、彻底断电都试过）。代码在、会自动探测，面板一旦恢复重新上电即自动启用 |
| **主界面定制**（车况条 + 3 套主题 + 语音切换） | 🔶 已关闭 | `ATZ_UI_ENABLE=0`。实现已验证过（含表情集挂载、间距、颜色），按要求回落到官方原版界面 |
| **射频端到端** | ⏳ 未验证 | 需要**第二块同型号板**跑主表固件，才能确认真实 ESP-NOW 广播能被收到。阶段 A 只证明了"收包之后"的逻辑正确 |
| **MCP 语音问答实测** | ⏳ 未验证 | 工具已注册，需联网对小智说"水温多少"实测 |
| 上车 | ⏳ | 见 `15-上车首测清单.md`，记得把热点/路由器锁**信道 1** |
