# 23 · 上游 AI 能力特性（整理 + 对本项目的标注）

> 整理自官方页面 [AI能力特性](https://xiaozhi.dev/docs/ai-features/) 与
> [Emoji 心情显示](https://xiaozhi.dev/docs/development/emotion/)（2026-09-18 抓取）。
> **官方原文是面向"整机产品"写的（很多数据是官方云服务/官方板的）**，所以本文做了两件事：
> ① 把散落的参数整理成表；② **每一节都标注"这块在我们这套硬件/固件里是什么情况"** ——
> 避免拿着官方数字去套我们这块 360×360 圆屏 + 自建链路的设备。
>
> ★ 官方页面的定位：它讲的是 **XiaoZhi 固件 + 官方云服务**的整机能力；
> 我们用的是**上游开源固件 + 自接服务端**，能力边界不同（见文末"哪些要打折扣"）。

---

## 一、整条 AI 链路（一张图看懂我们走的是哪几段）

```
① 语音输入（麦克风 I2S）
   ↓  本地
② 唤醒词（ESP-SR WakeNet，离线）
   ↓
③ 录音 + Opus 编码（16kHz 单声道，60ms 帧）
   ↓  网络（WebSocket 或 MQTT+UDP）
④ 云端 ASR（语音转文字）
   ↓
⑤ 云端 LLM（大模型：情绪 + 回复文本；工具调用走 MCP）
   ↓
⑥ 云端 TTS（文字转语音，Opus 下行）
   ↓  网络
⑦ 设备播放 + 屏幕表情（SetEmotion）+ 字幕（SetChatMessage）
```

**本项目每一段落在哪个文件**（想知道"改哪里"就直接照这张表走）：

| 段 | 上游讲的 | 我们这边对应 |
|---|---|---|
| ① 麦克风 | I2S + 编解码器 | 板级 `config.h` 的 I2S 引脚 + `GetAudioCodec()` |
| ② 唤醒词 | WakeNet，"你好小智" 等 26 种 | 同上（`CONFIG_USE_WAKE_WORD` + srmodels.bin，**在 assets 分区里**） |
| ③ 录音/编码 | Opus 16kHz / 60ms | 上游 `audio/` + `protocols/`，我们没动 |
| ④ ASR | 云端 | 官方/自建服务端，我们没动 |
| ⑤ LLM + MCP | 云端 + 工具调用 | **我们所有语音工具都注册在这一段**（`self.car.*` / `self.ui.*`，见 `20` 号文档 §7.1） |
| ⑥ TTS | 云端下行 Opus | 上游 `audio/`，我们没动 |
| ⑦ 表情/字幕 | `SetEmotion` / `SetChatMessage` | **我们重写了这两处的显示路径**：表情走 `atz_ui.cc` 的 `SetEmotion()`（可换素材，见 `22`），字幕加了"滚动 8 秒冻结 + 静置 30 秒清空"（见 `18` 缺陷 #34） |

## 二、官方参数表（照抄，别当成我们的实测值）

### 2.1 语音唤醒（WakeNet）

| 项 | 官方说法 |
|---|---|
| 默认唤醒词 | "你好小智" |
| 可选 | 26+ 种官方唤醒词（中/英/日/韩） |
| 响应 | < 200 ms |
| 待机功耗 | < 5 mA（**指官方整机**，含电源管理；我们这块板常亮背光，远不止） |
| 运行 | **完全本地**，不需要网络 |

改唤醒词：`idf.py menuconfig` → `Component config → ESP Speech Recognition → Wake Word Model Selection`
（我们这套工程是用 `scripts/build.py --wake-word <名称>`，见 `xiaozhi-ai/custom-board_zh.md` §5）

> ⚠️ 唤醒模型 `srmodels.bin` **装在 assets 分区里**（不在 app 分区）。
> 这就是为什么"换表情包"必须带上基线包 —— 否则会把唤醒词模型一起弄丢（见 `22` §三）。

### 2.2 语音识别（ASR）

| 项 | 官方说法 |
|---|---|
| 语言 | 中文（普通话/粤语）、英语、日语、韩语、俄语…（v2.0 后共 25+ 种） |
| 精度 | 中文 > 95%，英文 > 93%（云端 ASR，网络好时） |
| 音频格式 | **16 kHz、16 bit PCM**（上行编码成 Opus） |
| 离线/在线 | 混合：关键词离线、复杂语句在线 |

**多语言资源包结构**（`main/assets/locales/<lang>/`，每语言约 150 KB）：

```
zh-CN/
├── 0.ogg ~ 9.ogg     # 数字语音
├── welcome.ogg       # 欢迎
├── activation.ogg    # 激活成功
├── wificonfig.ogg    # WiFi 配置提示
├── upgrade.ogg       # 升级
├── err_pin.ogg       # PIN 错误
├── err_reg.ogg       # 注册错误
└── language.json     # 语言元数据
```

| 分档 | 语言 |
|---|---|
| Tier 1（优先优化） | 中文、英语、日语、俄语 |
| Tier 2（完整支持） | 西班牙语、法语、德语、韩语 |
| Tier 3（基础支持） | 保加利亚、加泰罗尼亚、丹麦、希腊、波斯、菲律宾、希伯来、克罗地亚、匈牙利、马来、挪威、荷兰、斯洛伐克、斯洛文尼亚、塞尔维亚、瑞典 等 17 种 |

配置语言（官方写法）：`CONFIG_XIAOZHI_LANGUAGE="zh-CN"`，或 menuconfig
→ `Xiaozhi Assistant → Language Settings → Select Language`。
**我们的写法**：`python scripts/build.py <板型> --language en-US`（可用 `--list-languages` 查）。

> 本项目现状：**中文 zh-CN**（默认）。要改语种重新编译即可，不影响车况功能。

### 2.3 大模型（云端）

| AI 模型 | 提供商 | 特色 | 成本 |
|---|---|---|---|
| DeepSeek-V3 | DeepSeek | 数学推理 / 代码生成 | 低 |
| Qwen-Max | 阿里云 | 中文理解 / 多模态 | 中 |
| Doubao-Pro | 字节跳动 | 对话生成 / 创作 | 中 |
| ChatGPT-4o | OpenAI | 通用智能 / 逻辑推理 | 高 |
| Gemini | Google | 多模态 / 实时交互 | 中高 |

> **选哪个大模型跟我们固件无关** —— 是**服务端**的配置。固件只负责"把工具描述给服务端、
> 执行服务端下发的 `tools/call`"（协议见 `xiaozhi-ai/mcp-protocol_zh.md`）。
> 但**模型强弱直接影响语音体验**：能不能听懂"我不想看进气"这类话、会不会主动调工具，
> 全靠它。这也是为什么我们的工具描述里把中文说法都列了出来（见 `20` §7.1）。

### 2.4 端侧 AI（官方标注"规划中"）

- TensorFlow Lite / 1–10 MB 量化模型 / 简单指令 < 100 ms。
- **现实**：这块板 **8 MB PSRAM + 内部 SRAM 只剩十几 KB**（见 `18` 缺陷 #36），
  跑端侧 LLM 不现实。**我们的"端侧智能"是规则引擎**，例如：
  `car_alarm.cc`（阈值告警，500 ms 评估一次）、`atz_trip.cc`（峰值保持）、
  `atz_car_page.cc`（车况页布局与字段开关）—— 都是本地、零延迟、不花 token。

### 2.5 视觉（v2.0 新增）

官方讲的是相机 + JPEG 优化（OV2640/OV3660/OV5640/GC032A 等）。

> **我们这块板没有摄像头**，用不上；但有一个**同源能力**值得知道：
> 设备截图 + 把图**上传给大模型看**——上游的 `self.screen.snapshot`（user-only 工具）就是干这个的。
> 我们另外加了本地只读端点 `/shot.jpg`（见 `20` §7），用于台架看屏。

## 三、官方"性能指标"那一节怎么读

官方页里那些数字（唤醒 <200ms、识别率 >95%、帧率/延迟提升百分比）是
**官方云服务 + 官方整机**在理想网络下的表现。放到我们这套上要看三件事：

| 官方数字 | 我们这边的现实 |
|---|---|
| 唤醒 < 200 ms | 关机；**唤醒本身是离线的**，实测可用（说"你好小智"→ 屏幕进"聆听中"） |
| 中文识别 > 95% | 取决于**你接的服务端**；网络抖动时明显变差（我们踩过 socket 耗尽导致"喊了没反应"，见 `18` 缺陷 #22） |
| 相机帧率/延迟提升 | 不适用（无摄像头） |
| 端侧推理 < 100 ms | 不适用（没跑端侧模型）；我们的**规则告警**是 500 ms 周期，等效延迟 < 1 s |
| 待机 < 5 mA | 不适用：圆屏常亮 + WiFi 常连，**我们的功耗远高于此**，车上取电即可 |

## 四、哪些"官方能力"我们**用不上 / 要打折扣**（避免照着官方文档白折腾）

| 官方能力 | 我们的情况 | 说明 |
|---|---|---|
| 端侧 AI 推理 | ✗ 不可行 | SRAM 太紧（`free sram: ~13KB`），PSRAM 又拿不到 DMA 刷新缓冲 |
| 相机 / AI 视觉 | ✗ 无硬件 | 板子没摄像头 |
| 蓝牙配网 BluFi | ⚠️ 可用但没启用 | 我们走**声波配网**（上游默认，见 `xiaozhi-ai/blufi_zh.md` 若要改用 BluFi） |
| 多语言语音包 | ⚠️ 只有 zh-CN | 换语种要重新编译（`--language`），且 assets 分区会变大 |
| 官方 OTA | ⚠️ 有 bug 记录 | 我们这版上游的 OTA 分块上传有 bug，见 `16-OTA分块上传bug与补丁.md` |
| 云端"发现新素材" | ✓ 已用起来 | 就是我们 `22` 号文档那套：写 `assets/download_url` → 开机下载 |
| Emoji 心情显示 | ✓ 已用起来 | 21 个情绪，对照表见 `22` §1.1；我们的告警还额外驱动表情 |
