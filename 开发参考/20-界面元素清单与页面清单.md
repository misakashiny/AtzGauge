## 一、页面清单

| 页面 | 怎么进 | 怎么出 | 实现位置 |
|---|---|---|---|

| **「行程」整屏页（第 2 页）** | **在车况页左划（←）**；或语音「看行程统计」→ `self.ui.show_trip_page`；或台架 `/carpage?page=1` | **向右划（→）** / `hide_car_page` / `/carpage?page=0` | 同上（同一页面的第二页） |
| 配网页 / 激活页 | 上游流程 | 上游流程 | 上游 `application.cc`（我们没碰） |
| 低电弹窗 | 电量低自动 | 自动消失 | 上游 `lcd_display.cc` 的 `low_battery_popup_` |

> 页面之间是"覆盖"关系：车况页是**独立全屏层**，盖在主界面上；隐藏它就回到主界面，
> 不会破坏主界面上的任何控件。
> ★ 两页共用同一个 `g_page` 容器，靠 `g_page_no`（0=车况 / 1=行程）切换；
>   切换时必须**同时隐藏两页各自的所有顶层控件**（行程页的状态行/按钮收在 `g_trip_hdr` 里）。
>
> ★★ **本项目的按钮怎么才会"点得动"**（2026-09-17 的坑，详见 `18` 缺陷 #28）：
>   全工程**没有给 LVGL 注册输入设备**（触摸不能交给 esp_lvgl_port，休眠的 CST816S 会 NACK →
>   重启循环），所以 `lv_button` 的 `LV_EVENT_CLICKED` 永远不会触发。
>   真正的点击链路是：`TouchPollTask`（30ms 轮询 + 解析坐标）→ `atz_hit_zone_test(x,y)`
>   → 命中区的回调（回调自己加显示锁）。**加新的可点控件时，必须在 `atz_car_page.cc` 的
>   `RegisterHitZones()` 里同步注册一块同位置的矩形**，否则按钮只是个画上去的方块。

## 三、「车况」页元素（实现于 `atz_car_page.cc`）

**布局是 flex 流式的（不是写死坐标）** —— 这样才能做到"语音关掉某一项之后自动重排、不留空位"。
LVGL 的 flex 会自动跳过 `HIDDEN` 的子控件，所以"不显示某项" = 给它加 `HIDDEN` 标志，其余全自动。

```
g_page（全屏黑底；g_page_no = 0 车况 / 1 行程）
│
├─【第 1 页 · 车况】
│  ├── g_link_label            顶部居中 y=−150，链路状态（"● 车况 10Hz"）
│  ├── g_col（flex 竖排，宽 232，TOP_MID @ y=56 → 项少了自动收缩并保持居中）
│  │   ├── g_hero_row（flex 横排）  转速 组 / 车速 组
│  │   └── g_grid（flex 横排换行）  其余字段，一格 108×31，两列自动换行
│  └── g_stale_label           底部 y=308「检查主表与信道」（仅无数据时显示）
│
└─【第 2 页 · 行程】
   ├── g_trip_hdr（头部容器，宽 360、高 66；**隐藏/显示它一个 = 隐藏整页头部**）
   │   ├── g_trip_title        「记录中」/「已暂停」y=2（绿/灰）
   │   └── btn_row             两个按钮 y=38：g_rec_btn「开始记录/暂停记录」+ g_reset_btn「清零重来」
   ├── g_trip_col（数据网格，宽 344，y=122 起）
   │   └── g_trip_grid         6 张卡片，一格 168×31，两列：里程/转速/车速/水温/油温/电压
   │       └── g_trip_status   点按钮后的提示（3 秒后自动隐藏）

```

| 内部名 | 位置 | 作用 |
|---|---|---|
| `g_page` | 全屏 360×360 | 整页容器（黑底），默认隐藏 |
| `g_link_label` | y=15 | 顶部链路状态：`● 车况 10Hz`（绿）/ `● 车况 无数据`（红）/ `● 车况 未连接`（红）；**行程页隐藏它** |
| `g_col` | TOP_MID @ y=56 | 内容列（flex column，宽 232）。★ 列宽与 y 是按圆屏四角判据解出来的 |

| `g_fields[i].cell` | 在 hero 行或 grid 里 | 每个字段的整格容器 —— **要"不显示某一项"就是隐藏它** |
| ~~`g_stale_label`~~ | — | **已删除**：与顶部链路状态重复，且原位置被上游低电量弹窗压住。现在"无数据"只在顶部一行表达（`● 未连接主表` / `● 主表已断流`，红字） |

| `g_trip_time` | y=30 | 行程页唯一的状态文字：`记录 0:00:20`（记录中=白、暂停=灰）。★ 原来的"记录中/已暂停"独立一行已删——状态改用**按钮底色**表达 |
| `g_rec_btn` | **y=228，132×30** | 「开始记录 / 暂停记录」按钮（真实点击区 x=43..175, y=224..262）。★ 实心填充：记录中=绿底深字，暂停=深灰底绿字 |
| `g_reset_btn` | y=228，132×30 | 「清零重来」按钮（真实点击区 x=183..315, y=224..262） |

**行程页的四个点击区**（`RegisterHitZones()`，坐标是屏幕绝对像素，可用 `/touch` 查）：

| 名字 | 矩形 | 动作 |
|---|---|---|
| `trip.record` | (43,224)-(175,262) | 行程页：开始/暂停记录 |
| `trip.reset` | (183,224)-(315,262) | 行程页：清零重来 |

**滑动手势（2026-09-18 起翻页只走滑动，页面内不再有翻页按钮）**：

| 当前页 | 左划（←） | 右划（→） |
|---|---|---|
| 主界面（表情页） | 打开「车况」页 | 不响应 |
| 「车况」页 | 进「行程」页 | **退回主界面（表情页）** |
| 「行程」页 | 不响应（已经是第二页） | 回「车况」页 |

- 实现：`atz_hit_zone.cc` 的 `atz_swipe_set_handler()`；每页切页时由
  `ApplyZoneEnable()` 重新注册，主界面由 `RegisterMainScreenGestures()` 清空 →
  手势落到触摸任务的兜底分支（主界面左划进车况页）。
- 手势判据（板级 `TouchPollTask`，**在手指抬起时判**）：
  位移 <20px → 点击；水平 ≥40px 且 ≥2×垂直 → 滑动；其它忽略。
  **必须等抬起**：滑动过程会一路划过很多控件，按下就触发会误按一堆按钮。
- 台架验证：`/swipe` 查当前注册情况、`/swipe?dir=left|right&key=` 合成一次滑动。

**行程页的数据来源与记录语义**（`atz_trip.cc`）：

| 项 | 说明 |
|---|---|
| 记录开关 | **开机默认关**（`ATZ_TRIP_RECORD_DEFAULT=0`）。语音「开始记录行程」/ 点按钮才累加 |
| 计时语义 | **只要在记录就按秒走**，与"有没有收到主表数据"无关（缺陷 #30：早先挂在数据新鲜度里，导致时长不跳） |
| 暂停 | **不清零**：数字原地停住，重新开始接着累加；只有「清零重来」/`reset_trip` 才清空 |
| 持久化 | RAM 累加 + 每 60 秒写 NVS（`ATZ_TRIP_SAVE_S`）；重启后峰值仍在，但**记录开关回到默认关** |
| 脏数据门控 | 主表超过 2 秒没数据就整拍跳过，绝不把 0 车速 / 哨兵温度（−40 / −100）当峰值 |
| 里程 | 对车速积分得到的**估算值**（没有里程表信号），标"约" |
| `hot_s` | 转速 ≥ `ATZ_TRIP_HOT_RPM`（6500）的累计秒数 |

**颜色语义**：白 = 正常 · 琥珀 `#FFA000` = 接近上限 · 红 `#FF3B30` = 超限 · 灰 `#5A5A5A` = 无数据
**阈值**（与告警模块一致）：水温 ≥108 / 油温 ≥125 / 转速 ≥6500 / 电压 ≤11.5 或 ≥15.0 → 红
**刷新**：300ms 一次；**超过 2 秒没收到主表数据 → 整页数值变灰显示 `--`**（绝不显示过期值）

## 四、圆形屏几何与遮挡（**改界面前必看**）

屏幕是圆的：设半径 R、离屏幕中心 dy 处，**真正能看见的宽度只有 `2·sqrt(R²−dy²)`**。

| 距中心 | 可用宽度 | 可视 x 范围 | 谁在这一带 |
|---|---|---|---|
| 0 px | 350 px | 5 .. 355 | 中央表情（140px，安全） |
| 60 px | 329 px | 16 .. 344 | |
| 100 px | 287 px | 36 .. 324 | |
| 120 px | 255 px | 53 .. 307 | |
| 140 px | 210 px | 75 .. 285 | |
| 150 px | 180 px | 90 .. 270 | **顶部状态行 / 时钟（y=28~70）** |
| 160 px | 142 px | 109 .. 251 | 上游原顶栏所在高度 |
| 170 px | 83 px | 138 .. 222 | 圆最窄的顶/底边 |

### 「字幕沿圆弧显示」的可行方案（灵感，尚未实施）

目标是让字幕贴合圆形边缘，而不是一条直线被两端切掉。

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. 逐字贴弧**（推荐做效果时用） | 把整句拆成单字 `lv_label`，第 i 个字放在角度 θᵢ = 90° + (i−(N−1)/2)·Δ，坐标 `x=180+R·cosθ, y=180+R·sinθ`；每个字用 `lv_obj_set_style_transform_rotation()` 旋转到切线方向 | 真正沿弧排布，**同样半径下能放更多字**（R=150 时底部 ±60° 弧长约 314px ≈ 20 个汉字） | ① 每字一个对象（20 字 = 20 个对象）；② 每次字幕更新要重排；③ 中英混排字宽不同，需用 `lv_txt_get_size()` 按字宽累加角度；④ 旋转是位图旋转，字会有轻微锯齿 |
| **B. 两行短句 + 分行限宽** | 不做曲线，把一句话切成两行，每行 ≤9 字；上宽下窄地匹配各自高度的弦长 | 实现最简（限宽 + 自动换行），立刻见效 | 仍是直排，"贴边"的观感一般 |
| **C. 沿弧走马灯** | 只在底部 ±60° 的弧段内排字，超长文本按窗口切片、每 300ms 移动一个字 | 兼顾"贴弧"与"长文本" | 需要自己做滚动与重排逻辑 |
| **D. 边缘留给状态、字幕回中央** | 圆边只放一圈状态指示（告警色环、进度弧 `lv_arc`），字幕回到最宽的中央区域 | 可读性最好、实现最省事 | 失去"贴边"的视觉效果 |
| **E. 弧形色环 + 短标签** | `lv_arc` 画环表示转速/水温等，环内侧只放 2~4 字短标签 | 适合"车上瞟一眼" | 信息量小 |

**建议顺序**：先 B（今天就能改完，立刻减少遮挡）→ 想要视觉效果再上 A（逐字贴弧）。
D 是"最稳"的退路：**圆形屏上，中央永远是最宽的地方**。

## 五、尺寸与缩放（当前值 + 实测）

> 这一节回答"到底放大了多少"。所有数字都是在真机上截屏量出来的，不是估算。
> 复现命令：`node D:\AtzGauge\tools\measure-sizes.mjs`

### 5.1 顶部时间（`status_label_`）

时间从"放大位图"改成了**换成更大的字体**，所以现在是**清晰的**，不是拉糊的。

| 阶段 | 做法 | 字号 | 实测文字像素 | 相对原版 |
|---|---|---|---|---|
| 官方原版 | 主题字 `_20_4` | 20 px | **48 × 14 px** | 基准 |
| 中间版本（已弃用） | `transform_zoom` 拉 140% | 仍是 20 px，位图放大 | **63 × 19 px** | +31%，但**发虚** |
| **当前** | 换成真字体 `font_noto_sans_basic_30_4` | **30 px** | **74 × 22 px** | **宽 +54% / 高 +57%，清晰** |

- 开关：`atz_ui_config.h` 的 `ATZ_CLOCK_SCALE_PCT`（默认 **140**）。
- `?clock=` 现在**只当开关用**：`≥125` → 30px 真字体，`<125` → 回到主题字（20px）。
  想要更大/更小，得先有对应字号的字体文件 —— 现成可用的只有 **14 / 16 / 20 / 30** 四档
  （`managed_components\78__xiaozhi-fonts\src\font_noto_sans_basic_{14_1,16_4,20_4,30_4}.c`）。
- 为什么 140% 会落到 30 px 字体：见 `atz_ui.cc` 的 `AtzLcdDisplay::SetStatus()` —— 它只在"当前文本是 `HH:MM`"时套大字体，
  其他状态文本（如"正在连接…"）仍用主题字（要大字体里没有的 CJK 字形），避免变成空白；
  同时把上面那条位图放大路径**复位成 256**，防止两套放大叠加。

### 5.2 各元素缩放当前值（实测）

| 项 | 基准 | 当前设定 | **实测结果** | 怎么调 |
|---|---|---|---|---|
| 表情图 | 素材 **128×121 px**（可见圆只有 111×108，PNG 四周有透明边距） | **125%** | 控件框 **160×151 px**；截屏里可见的圆 **140×134 px（比原版 +26%）** | 改 `atz_ui_config.h` 的 `ATZ_EMOJI_SCALE_PCT`，或运行时 `http://<设备IP>:8099/size?emoji=150` |
| 顶部时间 | 20 px 字号（line_height 28） | **140%（→ 30 px 字体）** | **74×22 px（比原版 +54%）** | 改 `ATZ_CLOCK_SCALE_PCT`，或 `?clock=160` |
| 车况条 | — | 宽 210 × 高 42，距底 54 | 与字幕栏间距 **11 px** | `ATZ_UI_CAR_BAR_*` 系列 |
| 字号档位 | 官方 16px | **20px** | 全 UI 生效 | `main/CMakeLists.txt` 我们那段（`_20_4` ↔ `_16_4`） |
| 表情素材 | 官方 64px | **128px** | 全 UI 生效 | 同上（`noto-color-emoji_128` ↔ `_64`） |

**实测方法（可复现）**：`node D:\AtzGauge\tools\measure-sizes.mjs`
它会依次设 100% / 125% / 150%，各截一张图并量出真实像素尺寸。

> ⚠️ 两个坑（都踩过，已修）：
> ① 只设 `lv_image_set_scale()` / `transform_zoom` **不够** —— 控件自身的绘制框仍是原尺寸，
>    放大的内容会被**裁掉**；必须同时把控件尺寸/高度撑开。
> ② 不能"等于 100% 就跳过不设" —— 那样**改回 100% 会失效**。

### 5.3 表情图为什么会糊（`emoji_image_`）

表情图是**位图**，放大就是把素材插值撑开，一定会软。素材集里只有 32 / 64 / 128 三档，
没有更大的，所以 125% 以上没有"原生分辨率"可用。

**实测（`/size` 端点直接读控件真实几何，不是估算）**：

| 百分比 | 控件框 | 100% 基准 |
|---|---|---|
| 100% | 128 × 121 px | 素材原始大小 |
| 110% | 140 × 133 px | +10% |
| **125%（当前）** | **160 × 151 px** | **+25%** |
| 140% | 179 × 169 px | +40% |

> 注意两个"尺寸"别混淆：**控件框**是 128×121 素材按百分比放大后的框；
> 截屏里能看见的**黄色圆**只有 140×134（比框小一圈，因为 PNG 四周是透明的）。
> 说"表情比原版大了多少"时，通常指后者：**约 +26%**。

| 方案 | 做法 | 效果 | 代价 |
|---|---|---|---|
| A. 保持 125%（当前） | 不动 | 140×134 px，轻微发虚 | 0 |
| B. 降到 110% | `ATZ_EMOJI_SCALE_PCT 110` 或 `/size?emoji=110` | 视觉上更"实"，仍比原版大 10% | 放大感变弱 |
| C. 自备大素材 | 加一套 192 / 256 px 表情集，改 `DEFAULT_EMOJI_COLLECTION` | **最清晰**，可放到 200% | 要自己做素材 + 占 Flash |

> 结论：**糊是素材分辨率的物理上限，不是代码 bug**。想"又大又清楚"只能走 C。
> （P.S. 顺带说明：`/size` 以前回显的是"128px 素材 × 百分比"的**推算值**，和截屏量出来的
> 数字对不上，容易误判成"缩放没生效"；现在改成读控件真实几何了。）

### 5.4 屏幕外沿的转速环（`g_arc`，参考 obd_brz_gauge）

> ★ **只有一个环**，而且**外缘贴屏幕边**。LVGL 的弧是"从对象半径往内画"，
> 所以直径必须取 **360**（外缘 = 半径 180 = 屏幕边），线宽 **26px** →
> 实测 9 点方向占 x=0..25（贴边、无空隙）。

| 项 | 数值 | 怎么调（`atz_ui_config.h`） |
|---|---|---|
| 环对象直径 / 线宽 | **360 px / 26 px** | `ATZ_RPM_RING_D` / `ATZ_RPM_RING_W` |
| 底槽不透明度 | 40 / 255（同色压暗） | `ATZ_RPM_RING_TRACK_OPA` |
| 满圈转速 | **8000 rpm** | `ATZ_RPM_RING_MAX_RPM` |
| 琥珀 / 红门槛 | **5500 / 6500 rpm** | `ATZ_RPM_RING_WARN_RPM` / `ATZ_RPM_RING_ALARM_RPM` |
| 取数节奏 | 100 ms（主表 10Hz） | `ATZ_RPM_RING_DATA_MS` |

- 打开「车况」整屏页时**自动隐藏**，回到主界面自动恢复（`atz_car_page_show/hide` 里联动）。

### 5.5 流畅度是怎么提上来的（实测数字，改前先看这条）

| 措施 | 说明 | 效果 |
|---|---|---|
| ① 自研插值（不用 `lv_anim`） | `lv_anim` 的节拍由**编译期** `LV_DEF_REFR_PERIOD`（33ms）决定 → 动画天生锁 30fps。改成自己按 **12ms** 步进做指数逼近 | 动画不再被 30fps 天花板卡住 |
| ② FreeRTOS tick 100 → **1000 Hz** | `esp_lvgl_port` 的任务循环里有一句 `vTaskDelay(1)`；tick=100Hz 时这一句就固定吃掉 **10ms/轮** | 这是**最大的一刀**，见下 |
| ③ 板级 `sdkconfig_append` 打开 | 在**本项目板型**的 `config.json` 里加 `CONFIG_FREERTOS_HZ=1000`（不影响其它板型、不动上游文件） | 生效后帧率翻倍 |
| ④ 刷新周期 33 → **2 ms** | `lv_display_get_refr_timer()` + `lv_timer_set_period()` 运行时改 | 缩短"失效→重绘"的等待 |
| ⑤ 重绘死区 | 静止时不写控件 | 空闲 **0 帧/秒** |

**实测（`/perf?seconds=6`，转速扫掠中）**：
`8.1 fps` → `33 fps` → `56.8 fps` → **`67~73 fps`**（单帧渲染+刷屏约 4~4.6 ms，
平均每帧只重绘 **2641 px** —— 说明瓶颈是"帧节奏"而不是"画得多"）。
空闲时 **0 帧**。想自己复核：`http://<IP>:8099/perf?seconds=6`。

### 7.2 PC 端「车况模拟台」（不用主表也能出数据）

`tools\sim-console.mjs`（双击 `tools\sim-console.cmd` 即用，界面 `http://127.0.0.1:8123`）：

- **滑块实时推数据**：转速/车速/水温/油温/进气/负荷/节气门/电压，10Hz 推给设备 → 走 `/inject`
  → 与真主表**完全同一条链路**（`espnow_slave_inject_test_packet` → 缓存 → 环/车况条/车况页/告警）

>
> 不需要这些调试端点时，把 `atz_ui_config.h` 的 `ATZ_UI_SHOT_SERVER_ENABLE` 置 0。

### 7.1 语音没反应时先查这里（★ 2026-09-16 的教训）

1. **看工具注册没有**：重启抓串口，`MCP: Add tool: self.ui.xxx` 有没有出现。
   没出现 = 被编译开关吃掉了或函数没被调用（缺陷 #19 就是这么被找到的）。
2. **用等价端点验证功能本身**：`/carbar`、`/carpage`、`/size`、`/theme`、`/perf` 每一条都对应一个语音工具。
   端点通、语音不通 → 问题一定在"工具注册/描述"这一层，不在功能实现。
3. **看大模型有没有调用**：工具描述里要把用户可能说的中文说法列出来（我们的工具描述都写了
   `"我不想看进气" -> field="intake"` 这类映射），否则大模型容易只回一句"好的"却不调工具。
