# 22 · 表情包素材规范与「一键推送」（换表情不用重刷固件）

> 面向"我想找点表情包换上去"这件事，把三件事说清楚：
> **① 你要准备什么素材 → ② 工具怎么用 → ③ 换坏了怎么回去。**
>
> 配套工具：`tools\emoji-kit.mjs`（本项目新增）
> 实测状态：**已跑通**（2026-09-18，用纯色方块验证过整条链路：本地服务器 → 设备下载 →
> 校验 → 应用 → 屏幕真的变了）

## 一、你需要准备的素材（就这些）

### 1. 文件名 = 21 个固定名字（这是唯一的"契约"）

```
angry      confident  confused   cool       crying     delicious  embarrassed
funny      happy      kissy      laughing   loving     neutral    relaxed
sad        shocked    silly      sleepy     surprised  thinking   winking
```

- 文件名必须**一字不差**（`happy.png` 不是 `Happy.png`、不是 `开心.png`）。
- 设备是按名字查图的：小智说"开心" → 服务端下发 `emotion=happy` → 显示 `happy.png`。
- **可以只给一部分**：缺的自动用内置图补上（风格会不统一，但不会崩）。

一条命令看清单：`node tools\emoji-kit.mjs --list-builtins`

### 2. 图片规格

| 项目 | 要求 | 说明 |
|---|---|---|
| 格式 | **PNG**（32 位带 alpha） | GIF 也能打包，但设备是用普通图片控件显示的，**动画不会播**；想要动图得改代码 |
| 尺寸 | **128 × 128**（推荐） | 固件把素材按 **125%** 放大到 160px 显示；给 128 正好。内置素材是 128×121（历史遗留，非正方形会被轻微拉伸） |
| 最小 / 最大 | ≥ 96、≤ 512 | 小于 96 会明显糊；大于 512 白占空间（屏幕最多用到 ~160） |
| 背景 | **透明** | 圆屏是深色底，带白底的图会像贴了张纸；切浅色主题时更明显 |
| 长宽比 | 尽量 1:1 | 超过 8% 的偏差工具会提醒（会被拉伸） |
| 单张体积 | 10~30 KB 合适 | 21 张 ≈ 200~600 KB；assets 分区 8 MB，当前占用约 1.7 MB |
| 不要 | 隔行扫描 PNG | LVGL 解不了，工具会直接拦住你 |

### 3. 目录长这样就行

```
D:\表情包\方案A\
    angry.png  confident.png  crying.png  ...  happy.png  ...  winking.png
```
（不要求 21 个齐全，不要求顺序，子目录不认）

## 二、一键推送：三条命令

> 前置：PC 和设备在**同一个 WiFi/网段**（设备 IP 见启动日志 `WifiStation: Got IP`）。
> 工具的默认设备 IP 是 `192.168.5.129`，不是的话加 `--device <IP>`。

### ① 先体检（不动设备，安全）

```powershell
cd D:\AtzGauge
node tools\emoji-kit.mjs --check "D:\表情包\方案A"
```
会告诉你：缺哪些名字、哪些不是 PNG / 隔行 / 太小 / 长宽差太多 / 没透明通道。

### ② 打包（还不推送）

```powershell
node tools\emoji-kit.mjs --dir "D:\表情包\方案A" --dry-run
```
产物落在 `backup\emoji-kit\assets.bin`，并打印体积、校验和、自检结果。
（缺名字时加 `--allow-missing`；它就自动补齐基线里的原图。）

### ③ 推送 + 重启设备（**一条命令搞定**）

```powershell
node tools\emoji-kit.mjs --dir "D:\表情包\方案A"
```
它会依次做：体检 → 打包 → 起本地 HTTP（默认 8124）→ 给设备写下载地址 → 重启设备。
设备**开机时**自动下载（日志 `Assets: Downloading new version of assets from …`，
进度 1% 一跳），下完 apply，表情就换了。整个过程 **约 25 秒**。

**只起服务器、自己在设备上操作**（比如你想边看边试）：

```powershell
node tools\emoji-kit.mjs --dir "D:\表情包\方案A" --no-push
# 然后对小智说：「把素材下载地址设成 http://<你的PC IP>:8124/assets.bin」
# 再重启设备（或对小智说「重启」）
```

**只换包不重新打包**（上一次已经打好了）：
```powershell
node tools\emoji-kit.mjs --serve-only     # 起服务器
```

### 常用参数

| 参数 | 作用 |
|---|---|
| `--check <目录>` | 只体检 |
| `--list-builtins` | 列出 21 个必需名字 |
| `--dry-run` | 打包但不推送 |
| `--no-push` | 打包 + 起服务器，不自动推 |
| `--serve-only` | 只起服务器（用上一次的 `assets.bin`） |
| `--allow-missing` | 缺素材也照打包（缺的用内置图补） |
| `--port 8125` | 换端口（8124 被占用时） |
| `--device 192.168.5.130` | 指定设备 IP |
| `--base <path>` | 换基线包（默认用 `build/generated_assets.bin`） |

## 三、它到底做了什么（原理，出问题时看这段）

小智上游本身就支持**运行时换素材**，我们的工具只是把准备工作全包了：

```
① 工具：把 21 张 PNG + 现有固件里那份 assets.bin 的其余内容
        （srmodels.bin 唤醒词模型 + 20px 字体 + index.json）重新打成一个 assets.bin
② 工具：起本地 HTTP 提供这个文件
③ 工具：往设备写 NVS  settings("assets")/download_url = http://<PC>:8124/assets.bin
        （后端就是上游的 self.assets.set_download_url，我们加了 /assets 端点走 HTTP）
④ 设备重启 → Application::CheckAssetsVersion() 发现有地址 → Assets::Download()
        流式下载（边下边擦边写，约 130 KB/s，1.7 MB 约 13 秒）→ 覆盖 assets 分区
⑤ 下载完 InitializePartition() 重新 mmap + 校验和 → Apply() 加载新表情/字体 → 生效
⑥ 地址用完即擦（所以是"一次性"的，失败也不会一直重试）
```

**★ 为什么必须带上基线（不能只放表情）**：设备端 `Apply()` 是从**同一个 assets 分区**里
读 `index.json` / `srmodels.bin` / 字体文件的。如果我们的包里只有表情，那三样就没了 ——
唤醒词模型加载失败、字体回退。所以工具默认以 `build/generated_assets.bin`（当前固件的
那份）为基线，**只替换 21 张表情图**。

**★ 校验保护**：assets.bin 自带一个 16 位校验和（表区+数据区所有字节累加）。下载不完整/
格式不对时，设备会打印 `The calculated checksum … does not match` 并**拒绝应用**，
继续用旧素材（不会变砖）。工具打包后也会本地自检一遍（能按设备端逻辑完整解析）。

**设备侧相关端点**（本项目新增，见 `20` 号文档 §7）：

| 端点 | 作用 |
|---|---|
| `/assets` | 只读：当前待下载地址 |
| `/assets?url=…&reboot=1&key=…` | 写下载地址并重启（工具用的就是它） |
| `/assets?clear=1&key=…` | 取消待下载 |
| `/assets?progress=42&key=…` | 让 PC 工具把进度显示在设备字幕上 |

## 四、换坏了 / 想回到内置表情

**不用重刷固件。** 用内置素材当"自定义"再推一次即可：

```powershell
# D:\AtzGauge\backup\emoji-test 里就是内置素材的副本（工具测试时留下的）
node tools\emoji-kit.mjs --dir "D:\AtzGauge\backup\emoji-test" --allow-missing
```
或者直接**重刷一次完整固件**（assets 分区会被一并写回内置内容）：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\idf-run.ps1 `
  -Command "cmd /c tools\flash-atzgauge.bat"
```

**底线**：这台设备上换素材**不会变砖**——最坏情况是校验失败继续用旧素材，或者表情显示不出来
（回退字体图标）。真出问题，重刷固件即可。

## 五、想要"永久内置"（不依赖下载）

选定方案后，把 21 张 PNG 放进板型目录并让构建用它，这样以后每次刷机都自带：

1. 新建 `xiaozhi-esp32\src\main\boards\waveshare\esp32-s3-touch-lcd-1.85-atzgauge\emoji\`，
   把 21 张 PNG 放进去；
2. 在**板型目录外**的那处 `main/CMakeLists.txt` 分支里把 `DEFAULT_EMOJI_COLLECTION`
   指向它（属于上游改动，`mods-atzgauge` 会记录）；
3. 重新编译烧录。

> 这一步我还没做（当前是"运行时推送"方案）。等你定稿素材后我再改，改完 `generated_assets.bin`
> 里就自带你的表情，`emoji-kit` 仍然可以随时覆盖它做实验。

## 六、实测记录（2026-09-18）

| 步骤 | 结果 |
|---|---|
| 内置素材打包 + 自检 | 25 个文件、1736.1 KB、校验和 0x85e、25 条全部可解析 ✓ |
| 推送 + 重启下载 | `Progress: 7% → 87%`，约 130 KB/s，位置/速度与擦除扇区数都正常 ✓ |
| 应用 | 重启后 `assets map size 1792 KB`、`checksum calculation 107 ms`、无校验错 ✓ |
| **视觉验证** | 临时把 `neutral/happy/sad` 换成纯绿/红/蓝方块推上去 → 屏幕出现**纯绿色方块**（就是新素材），证明真的换了 ✓ |
| 回退 | 再推一次内置素材 → 屏幕恢复黄色笑脸 ✓ |

> 过程中踩的两个坑（已修）：
> ① 用 `Start-Job` 起服务器，**PowerShell 会话一结束 job 就被回收**，设备连不上（第一次
>    下载报 `Connection failed`）→ 必须用 `Start-Process` 起独立进程；
> ② 我第一版自检里算绝对偏移时多加了表长，误报"缺少 0x5A5A 前缀"（打包本身是对的）。
