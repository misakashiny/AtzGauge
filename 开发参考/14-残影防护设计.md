# 残影防护设计（LCD image retention guard）

> 背景：这块 360×360 IPS TFT 长期显示**固定位置的高对比静态元素**（白圈表框、固定位置大号数字、表盘弧线），
> 且车上长期通电 —— 属于 LCD 残影的典型诱因。见 `12` 号文档里的原理说明。
> 本文只讲**改哪里、怎么改、怎么验证**。全部改动都需要 ESP-IDF 编译（见 `02`）。

---

## 〇、先明确：不是 OLED 烧屏

| | OLED 烧屏 | **本机 LCD 残影** |
|---|---|---|
| 成因 | 有机发光材料不可逆衰减 | 液晶盒内离子迁移 + 内建直流偏压 |
| 可逆 | ❌ | ✅ **断电静置可恢复** |

所以目标是**延缓积累**，不是"防止永久损坏"。**越早做越好**——等残影出来了再改就晚了。

---

## 一、现状盘点（能直接用的东西比想象中多）

| 能力 | 位置 | 状态 |
|---|---|---|
| 背光 PWM 调光 | `ST77916.c` → `Set_Backlight(uint8_t 0~100)` | ✅ **现成可用** |
| 背光淡入淡出 | `Backlight_Init()` 里已 `ledc_fade_func_install(0)` | ✅ 可直接 `ledc_set_fade_with_time` |
| 背光引脚 | `EXAMPLE_LCD_PIN_NUM_BK_LIGHT = GPIO5` | ✅ |
| 默认亮度 | `LCD_Backlight = 70`；实际取 NVS 的 `brightness_day` | ✅ |
| NVS 亮度字段 | `uint8_t brightness_day;  // 10-100, 0=unset(use 100)` | ✅ 已有 |
| NVS 预留字段 | `uint8_t rsv[4]` / `uint8_t rsv[2]` | ✅ 可用来加新配置 |
| 主循环挂钩 | `ui.c` → `lv_timer_create(my_timerMain, ui_refresh_period_ms_for_screen(...))` | ✅ 按页面 16/33/50/200ms |
| 页面切换 | `_ui_screen_change(&ui_ScreenPageXxx, ...)` | ✅ 现成 |
| 背光已有一处调用 | `ui.c:841` 开机 500ms 后按 `brightness_day` 点亮一次 | ✅ 只跑一次（`ucOnlyOnce`） |

**结论：不需要碰驱动层，全部改动都在应用层（`ui.c` / `ui_ext.c` / `nvs_storage.h`）。**

## 二、措施 1：静止自动降亮 ⭐ 首选

**原理**：离子迁移速率随亮度（电场强度）下降而显著降低。停车时把背光压到很低，是最省事、最有效的一招。

### 触发逻辑

```
每次 my_timerMain 被调用：
  now = 当前毫秒

  if (车速 > 0 || 触摸事件发生)  last_active_ms = now     // 任一条件刷新活跃时刻

  idle = now - last_active_ms

  if (idle > DIM_TIMEOUT && 当前亮度 != DIM_LEVEL)
      淡变到 DIM_LEVEL                    // 建议 10~15%
  else if (idle <= DIM_TIMEOUT && 当前亮度 != brightness_day)
      淡变回 brightness_day
```

### 关键细节

- **`车速 == 0` 不能单独作为判据**：等红灯、堵车时也是 0。必须叠加"无触摸"才算闲置。
  建议判据：**`speed == 0` 持续 N 分钟 且 期间无触摸**。
- **触摸检测**：LVGL 的输入设备有活动时间。最省事的做法是在 `my_timerMain` 里读
  `lv_indev_get_state(lv_indev_get_act())`，或在各页面的 `LV_EVENT_PRESSED` 里打时间戳。
  更稳的是查 LVGL 8 的 `indev->proc.types.pointer.last_act_time`（表示最后一次输入时刻）。
- **淡变而不是跳变**：`ledc_fade_func_install(0)` 已装，用
  ```c
  ledc_set_fade_with_time(LEDC_LS_MODE, LEDC_HS_CH0_CHANNEL, Duty, 800);  // 800ms
  ledc_fade_start(LEDC_LS_MODE, LEDC_HS_CH0_CHANNEL, LEDC_FADE_NO_WAIT);
  ```
  可直接在 `Set_Backlight()` 旁加一个 `Set_Backlight_Fade(light, ms)`。
  ⚠️ 注意 `Set_Backlight` 内部的占空比换算是 `LEDC_MAX_Duty - 81*(100-Light)`，
  亮度 ≤ 1 时会被强制置 0（全灭），别把 DIM_LEVEL 设成 0/1。
- **不要降到全灭**：熄火后如果还想看时间/电压，留 10~15% 比全黑更实用。

### 需要新增的 NVS 字段（用预留位或尾部追加）

```c
uint8_t  dim_timeout_min;   // 0=关闭该功能；建议默认 5（分钟）
uint8_t  dim_brightness;    // 变暗后的亮度，建议默认 15；0=用内置默认
```

> ⚠️ **改 NVS 结构体必须走版本迁移**。`nvs_storage.c` 里已有 v0→v1→v2 的迁移逻辑
> （见其头部注释："struct grew; rewrite NVS at the new size"）。
> **追加字段到结构体末尾**，并沿用现有的迁移写法，否则老设备的配置会被读坏。

## 三、措施 2：停车时轮换页面

**原理**：残影来自"同一区域长期同一亮度"。让整屏内容周期性大范围变化，等于不断打断离子积累。

### 逻辑

```
若 闲置（同措施1的判据）且 当前在只读数据页：
    每 60~120 秒 _ui_screen_change() 切到下一个只读页
```

**只读页白名单**（绝不能切进会改设置的页面）：

```
Gear → RPM → Speed → Temp → Info → (回到 Gear)
```

**排除**：设置页、各 Config 页、BLE SCAN、OTA Mode、彩蛋页、报警配置页。

### 注意

- 轮换会打断用户主动浏览 —— 所以**只在闲置态轮换**，一有触摸立即停止轮换并停在当前页。
- 页面切换本身会重建对象、有内存开销；60 秒一次可以忽略。
- 如果已经启用了措施 3（像素偏移），两者叠加效果更好。

## 四、措施 3：像素偏移（需先确认移植层）

**原理**：把整屏画面平移 1~2px，让"一直在同一处发光"的液晶区域换位。

### ⚠️ 先确认再动手

LVGL 8 与 LVGL 9 在这点上不同：**LVGL 9** 有 `lv_display_set_offset()`；
**LVGL 8 的 `lv_disp_drv_t` 没有直接的整屏偏移字段**。仓库用的是 LVGL 8.3.x。

动手前先确认两件事：

1. **LVGL 移植层在哪** —— `ST77916.c` 只注册了 `on_color_trans_done` 回调，
   真正的 `lv_disp_drv_t` 初始化在别处（`ui.c` 或独立的 lvgl_port 文件），先找出来。
2. **flush 回调是否可控** —— 如果 flush 走 `esp_lcd_panel_draw_bitmap`，
   可以在设置地址窗口时给 x/y 加偏移。但面板正好 360×360，偏移会把边缘推出屏外。

### 更稳的替代做法

对**当前屏幕的最外层对象**做 translate 抖动：

```c
// 每 60 秒在 4 个角之间循环
static const int8_t dx[4] = {0, 1, 0, -1};
static const int8_t dy[4] = {1, 0, -1, 0};
lv_obj_set_style_translate_x(scr, dx[i], 0);
lv_obj_set_style_translate_y(scr, dy[i], 0);
```

**代价**：圆屏四角本来就被裁掉，±1px 基本无感；但主题素材（`ring.png`）边缘只留 2~4px 余量，
偏移超过 2px 会蹭到边。**所以偏移量固定 ±1px，别贪多。**

## 五、措施 4：主题层规避（零代码）

已经写进 `13-主题模板与素材清单.md`：

- `bg` **不要用** `0x000000` 纯黑、`ring` **不要用** `0xFFFFFF` 纯白 —— 那是最高对比组合
- 出厂 `DEFAULT` 主题恰好是纯黑+纯白（`bg=0x000000`, `ring=0xFFFFFF`, `arc_indicator=0xFFFFFF`）
- `AMBER` / `OCEAN` 的低对比配色从护屏角度更友好

## 六、优先级与实施建议

| 措施 | 效果 | 改动量 | 风险 | 建议 |
|---|---|---|---|---|
| **1 静止自动降亮** | ★★★★★ | 小（应用层 + 2 个 NVS 字段） | 低 | **先做这个** |
| **2 停车轮换页面** | ★★★★ | 小（复用现成切页） | 低 | 与 1 一起做 |
| 3 像素偏移 | ★★★ | 中（要先摸清移植层） | 中（可能蹭边） | 确认后再做 |
| 4 主题配色规避 | ★★ | 零（改 JSON） | 无 | **现在就做** |

**推荐先落地 1 + 2 + 4**，这三项就能覆盖绝大部分收益，且全在应用层、可控、可回退。
措施 3 留到摸清 LVGL 移植层之后再说。

## 七、怎么验证（不用上车）

| 验证项 | 方法 |
|---|---|
| 降亮是否触发 | 拔掉 OBD/Vgate（车速恒为 0），不碰屏幕，等 `dim_timeout_min` 分钟后看串口日志 + 肉眼 |
| 唤醒是否恢复 | 点一下屏幕 → 亮度应淡变回 `brightness_day` |
| 轮换是否只在只读页 | 停在设置页放 5 分钟，确认**不会**被切走 |
| NVS 迁移是否安全 | 刷入新固件后确认原有设置（主题、阈值、profile）**全部保留** |
| 残影本身 | **现在没法主动验证**（要几十小时静态显示才显现）。所以是"预防"而非"修复" |

## 八、顺带发现：`ble_obd_mac` 字段已存在

排查残影时在 `nvs_storage.h` 里看到：

```c
uint8_t ble_obd_mac[6];  // paired ELM327 exact MAC (all-zero = unbound, fuzzy-match by ble_device_name)
```

**这解释了我们实测到的现象**：仪表在没有任何绑定 MAC 的情况下**会自动连上一台陌生 BLE 设备**
并空跑 `ATSP1~12` 协议探测 —— 因为 MAC 全零时走的是"按名字 fuzzy-match"分支。

而 main 源码里 `match_device_target()` 的注释却写着
`"Only exact MAC matches: never auto-connect when no MAC is bound (no fuzzy name matching)"`。

**两者矛盾**：要么发布的固件（count 104）比 main 源码旧，要么这段逻辑没生效。
**无论如何，`ble_obd_mac` 字段已经存在，说明"精确 MAC 绑定"这条路是通的** ——
上车前把 Vgate 的 MAC 写进去，就能根治连错设备的问题，不用改协议层。
（这条留给做 ATENZA profile 时一并处理。）
